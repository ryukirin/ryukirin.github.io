## 笔记 - 第四章 智能体经典范式构建

### 三种代表性架构范式

- ReAct: 先思考，再采取行动，之后观察结果决定下一步行动，整体在循环中进行
- Plan-and-Solve: 先列计划再按步执行
- Reflection: 通过反思来优化结果

#### 已有框架的限制

- 高度抽象，属于把各种逻辑装在壳子里，只留外部接口给用户，无法深入理解运行机制
- 有些框架如果还在不稳定期间，容易有破坏性更新
- 需要高度自定义的场景还是自己手搓一个比较直接

### ReAct

- Thought (思考): 思考
- Action (行动): 决定采取什么行动
- Observation (观察): 执行行动，提供结果

适用场景

- 需要外部知识的任务
- 需要精确计算的任务
- 需要与API交互的任务

#### 特点

- 思考过程可以观测，透明度高，方便找到改进方向
- 动态规划能力，可以根据结果改变计划（下一步）

#### 局限性

- 依赖 LLM 能力
- 执行时间久，消耗高
- 依赖提示词
- 容易陷入局部最优解问题，没有长久规划能力，还可能钻牛角尖

### Plan-and-Solve

先列规划再执行

规划器 `Planner` 负责生成 plan，执行器 `Executor` 负责执行任务，并且进行状态管理

因此执行器需要保留完整计划和各个步骤执行结果以及当前进度

示例 prompt

```python
EXECUTOR_PROMPT_TEMPLATE = """
你是一位顶级的AI执行专家。你的任务是严格按照给定的计划，一步步地解决问题。
你将收到原始问题、完整的计划、以及到目前为止已经完成的步骤和结果。
请你专注于解决“当前步骤”，并仅输出该步骤的最终答案，不要输出任何额外的解释或对话。

# 原始问题:
{question}

# 完整计划:
{plan}

# 历史步骤与结果:
{history}

# 当前步骤:
{current_step}

请仅输出针对“当前步骤”的回答:
"""
```

#### 局限性

一开始的计划很重要，规划错了就会一直错

### Reflection

自我校对模式，先完成任务，再进行自我 review，之后根据 review 结果进行改善

也是在循环中进行，直到没有新的问题为止 -> 这样就会有概率陷入死循环，所以最好设置最大循环次数

可以和上边两种范式相结合使用
