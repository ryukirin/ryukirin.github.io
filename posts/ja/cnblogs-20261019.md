### 第 5 章 サブ Agent とコンテキストの分離：Agent に委任を学ばせる

サブ Agent を設計した主な動機はコンテキストの分離である。サブ Agent は結果だけを返し、ツール呼び出しや思考の過程は返さない

そのため、複雑なタスクではサブ Agent を使う効果が大きい。単純な質問ではかえって時間がかかり、サブ Agent のプロンプトの分も余計に消費する

#### サブ Agent の定義

```python
from deepagents import create_deep_agent

# リサーチ用のサブ Agent を定義
research_subagent = {
    "name": "researcher",                # 必須：一意の識別子
    "description": "特定のテーマを深く調べ、複数の情報源を検索して要約にまとめる",  # 必須：メイン Agent はこれを見て委任するかを決める
    "system_prompt": """あなたはプロの研究者です。あなたのタスクは次のとおりです。
1. 研究課題を複数の検索クエリに分解する
2. internet_search で関連情報を検索する
3. 調べた内容を簡潔な要約にまとめる
4. 主な発見と情報源を列挙する

注意：結果は 500 字以内に収め、核心となる発見だけを返すこと。""",  # 必須：サブ Agent 自身の指示
    "tools": [internet_search],          # 省略可。デフォルトは継承。明示すると完全に置き換わる（マージされない）
    "skills": ["/skills/research/"],     # 省略可。メイン Agent からは継承しない。指定すると独立して SkillsMiddleware を実行
}

agent = create_deep_agent(
    model="google_genai:gemini-3.1-pro-preview",
    skills=["/skills/main/"],            # メイン Agent と general-purpose サブ Agent がここを継承
    subagents=[research_subagent],       # researcher は /skills/research/ だけを持ち、/skills/main/ は持たない
)
```

- サブ Agent の system_prompt はメイン Agent から継承されないので、サブ Agent ごとに専用の指示を用意する
- skills も継承されない。メイン Agent の skills は general-purpose サブ Agent にだけ渡され、それ以外のサブ Agent は自分の skills パスを明示的に設定する必要がある
- tools はデフォルトでメイン Agent のツールセットを継承するが、一度明示的に指定すると**完全に置き換わる**（マージではない）
- permissions は省略すると親のルールを継承し、明示的に指定すると加算ではなく**丸ごと置き換わる**

#### General-purpose サブ Agent

Deep Agents にはデフォルトで general-purpose サブ Agent が付いている。このサブ Agent は、メイン Agent に明示的に渡された tools、model、skills を継承する

ミドルウェアについては、メイン Agent がデフォルトのミドルウェアを同名で上書きした場合にだけ、その上書きを継承する。つまりデフォルトにないミドルウェアは、メイン Agent に同名で設定しても general-purpose サブ Agent には渡されない

**general-purpose を無効にする**

general-purpose サブ Agent を使いたくない場合は、サブ Agent の仕組みごと無効にできる

```python
from deepagents import create_deep_agent
from deepagents.profiles import GeneralPurposeSubagentProfile, HarnessProfile, register_harness_profile

# 2 つの手順はどちらも必要
# 指定したモデルに Harness Profile を登録する。
register_harness_profile(
    key="openai:zai-org/GLM-5.2",
    profile=HarnessProfile(
        # excluded_middleware で SubAgentMiddleware を除外しないこと。ValueError がそのまま送出される
        general_purpose_subagent=GeneralPurposeSubagentProfile(
            enabled=False
        )
    ),
)

agent = create_deep_agent(
    model=model,
    subagents=[],  # 同期サブ Agent を 1 つも渡さない
)
```

**general-purpose を上書きする**

general-purpose にモデルやツールを指定したい場合は、同じ名前で上書きできる

```python
agent = create_deep_agent(
    model=model,  # メイン Agent はアプリのデフォルトモデルを使う
    tools=[internet_search],
    subagents=[
        {
            "name": "general-purpose",  # デフォルトを上書き
            "description": "汎用アシスタント。さまざまな委任タスクを処理する",
            "system_prompt": "あなたは汎用アシスタントです。",
            "tools": [internet_search],
            "model": ChatOpenAI(  # サブ Agent にはより強いモデルを使う
                model="zai-org/GLM-5.2",
                api_key=os.environ["SILICONFLOW_API_KEY"],
                base_url="https://api.siliconflow.cn/v1",
            ),
        },
    ],
)
```

**general-purpose で Todo を有効にする**

TodoListMiddleware はデフォルトのミドルウェアではないため、デフォルトでは有効にならない。有効にしたい場合は、TodoListMiddleware を持つサブ Agent を同じ名前で上書きする

```python
from deepagents import create_deep_agent
from langchain.agents.middleware import TodoListMiddleware

agent = create_deep_agent(
    model=model,
    middleware=[TodoListMiddleware()],  # メイン Agent の計画機能
    subagents=[
        {
            "name": "general-purpose",  # 自動で追加されるデフォルトのサブ Agent を上書き
            "description": "計画が必要な委任タスクを処理する",
            "system_prompt": "委任されたタスクの計画を立て、実行して結果を返してください。",
            "middleware": [TodoListMiddleware()],  # サブ Agent で個別に有効化
        },
    ],
)
```

#### CompiledSubAgent

より複雑な場面では、CompiledSubAgent を使って LangGraph のワークフローをサブ Agent として組み込める

渡す LangGraph グラフの State には `"messages"` キーが必要

```python
from deepagents import create_deep_agent, CompiledSubAgent
from langchain.agents import create_agent

# LangChain でカスタム Agent グラフを作る
custom_graph = create_agent(
    model=model,
    tools=[statistical_analysis, generate_chart],
    system_prompt="あなたはデータ分析の専門家で、統計分析と可視化を得意とします。",
)

# CompiledSubAgent として包む
data_subagent = CompiledSubAgent(
    name="data-analyzer",
    description="統計分析やグラフ作成を含む複雑なデータ分析タスクを実行する",
    runnable=custom_graph,  # コンパイル済みの LangGraph グラフを渡す
)

agent = create_deep_agent(
    model=model,
    subagents=[data_subagent],
)
```

#### 複数サブ Agent の協調パターン

メイン Agent がサブ Agent の作業を調整する

```python
        "tools": [internet_search, api_call],
    },
    {
        "name": "data-analyzer",
        "description": "集めたデータを統計分析し、重要な洞察を抽出する",
        "system_prompt": "あなたはデータ分析の専門家です。データを分析して重要な発見を 3〜5 個抽出し、300 字以内にまとめてください。",
        "tools": [statistical_analysis],
    },
    {
        "name": "report-writer",
        "description": "分析結果をもとに専門的なレポートを書く",
        "system_prompt": "あなたはテクニカルライティングの専門家です。提供された分析結果をもとに、明確で専門的なレポートを書いてください。",
        "tools": [format_document],
    },
]

agent = create_deep_agent(
    model=model,
    middleware=[TodoListMiddleware()],
    system_prompt="""あなたはプロジェクトのコーディネーターです。複雑なタスクでは次のようにしてください。
1. まず write_todos で計画を立てる
2. データ収集を data-collector に委任する
3. 分析作業を data-analyzer に委任する

    subagents=subagents,

```

#### 構造化出力

`response_format` フィールドを使うと、サブ Agent に Pydantic スキーマに沿った JSON を返させることができ、メイン Agent がプログラムで処理しやすくなる

```python
research_subagent = {
    "name": "researcher",
    "description": "特定のテーマを調べ、構造化した発見を返す",
    "system_prompt": "与えられたテーマを深く調べ、発見を返してください。",
    "tools": [internet_search],
    # 事前に定義したデータモデルのクラス
    "response_format": ResearchFindings,  # deepagents>=0.5.3 が必要
}
```

#### サブ Agent のベストプラクティス

- `"description"` は具体的に書く
- System Prompt は詳しく書く
- ツールセットは絞り込む
- タスクの性質に合ったモデルを選ぶ
- 返す結果は簡潔にする（そもそもコンテキスト分離のために使うものなので）
- **終了条件を明確にする（メイン Agent も同様で、各ステップの終了条件をはっきり書く）**

#### 所感

最近 Cursor の設定ファイルを読んでいて、サブ Agent はトークンを多く消費するという評価があったのを覚えている。コンテキストが共有されず、サブ Agent には専用のプロンプトもあるからだ。Cursor は基本的に対話が中心で、委任するタスクも比較的単純なので、その観点ではサブ Agent を使わないほうがかえってコストを抑えられるのだと思う。todo と同じく、有効にするにはコストがかかるので、見合うかどうかを考えて選ぶべきだろう。
タスクとサブ Agent の完了条件も重要で、それがないといつまでも実行が続いてしまう。

## 実践: AI ニュースアシスタントをサブ Agent に分割

Task2 の [AI ニュースアシスタント](https://github.com/ryukirin/ai-news-deep-agent) では、検索、重複チェック、履歴との照合、レポート作成の 4 ステップをメイン Agent が 1 つで担っていた。第 5 章を学んだあと、この 4 ステップを 4 つのサブ Agent にそれぞれ委任し、メイン Agent は計画、委任、結果の統合を受け持つようにした。

リポジトリ: [ryukirin/ai-news-deep-agent](https://github.com/ryukirin/ai-news-deep-agent)

### サブ Agent の役割分担

| サブ Agent       | 担当するステップ                                                          | モデル                           | 返す形式   |
| ---------------- | ------------------------------------------------------------------------- | -------------------------------- | ---------- |
| news-collector   | ニュースを検索し、最大 10 件集める                                        | `structured_model`               | `NewsList` |
| news-categorizer | 集めたニュースに重複がないか確認する                                      | `structured_model`               | `NewsList` |
| old-news-checker | `/history/news_history.txt` と照合し、過去のニュースを除いて新しい記録を追記する | `structured_model`               | `NewsList` |
| report-generator | ニュースをもとにレポートを書く                                            | メイン Agent の `model` を継承 | テキスト   |

- 4 つのサブ Agent はどれも `tools` を指定しておらず、メイン Agent の `internet_search` と `get_current_time` を継承する
- news-collector には `ToolCallLimitMiddleware` を付け、1 回の実行で `internet_search` を呼べるのは最大 10 回にした。`exit_behavior="continue"` は、上限に達したら検索をやめてサブ Agent の処理を続けるという意味
- 最初の 3 つのサブ Agent は `response_format` で `NewsList` の構造に沿った JSON を返すので、次のステップのサブ Agent は同じ形式のニュース一覧を受け取る

### メイン Agent とサブ Agent のプロンプト

`config.py` の質問はステップごとに委任する形に変え、4 つのサブ Agent の system_prompt もここに置いた。

```python
USER_PROMPT = """
1. ニュース収集の作業を news-collector に委任し、関連ニュースを 10 件集めたら次のステップへ進む
2. 集めたニュースを news-categorizer に渡して重複をチェックし、重複がなければ次のステップへ進む
3. 整理したニュースを old-news-checker に渡して過去のニュースかどうかを確認し、過去のニュースがなければ次のステップへ進む
4. レポート作成を report-generator に委任し、{当日の日付}.md というレポートにまとめて report/ フォルダに保存する
"""

NEWS_COLLECTOR_PROMPT = "あなたはニュース収集の専門家です。関連ニュースを検索して整理し、構造化したニュース記事を返してください。収集するニュースは最大 10 件です。"
NEWS_CATEGORIZER_PROMPT = """あなたはニュース分類の専門家です。集めたニュースに重複がないか確認してください。
- 重複があれば 1 件を削除する
重複のない構造化したニュース記事の一覧を返してください。"""
OLD_NEWS_CHECKER_PROMPT = """あなたはニュース審査の専門家です。集めたニュースが /history/news_history.txt にある過去のニュースかどうかを確認してください。
- 過去のニュースでなければ、ニュースのタイトル、要約、出典を /history/news_history.txt に追記する。
- 過去のニュースであれば、そのニュースは飛ばす
過去のニュースを含まない構造化したニュース記事の一覧を返してください。
"""
REPORT_GENERATOR_PROMPT = "あなたはニュースレポートの専門家です。収集・分類したニュース記事をもとに総合レポートを作成し、レポートの内容を返してください。"
```

### 構造化出力

`data_model.py` でサブ Agent が返すニュース一覧を定義した。

```python
from pydantic import BaseModel, Field

class NewsArticle(BaseModel):
    title: str = Field(description="ニュース記事のタイトル")
    content: str = Field(description="ニュース記事の内容")
    source: str = Field(description="ニュース記事の出典")

class NewsList(BaseModel):
    articles: list[NewsArticle] = Field(description="ニュース記事の一覧")
```

### Agent

Task2 のコードにサブ Agent の定義を加えた。`response_format` を使うサブ Agent には思考モードを切ったモデルを使っており、理由はコメントに書いてある。

```python
# DeepSeek の思考モードは tool_choice="required" に対応していないため、response_format を使うサブ Agent は非思考モードにする
structured_model = ChatOpenAI(
    model=config.MODEL_NAME,
    api_key=config.DEEPSEEK_API_KEY,
    base_url=config.BASE_URL,
    extra_body={"thinking": {"type": "disabled"}},
)

# サブ Agent の一覧を定義。model / tools を指定しなければ、メイン Agent のモデルとツールを自動で継承する
subagents = [
    {
        "name": "news-collector",
        "description": "複数の情報源から関連ニュースを集める",
        "system_prompt": config.NEWS_COLLECTOR_PROMPT,
        "model": structured_model,
        "middleware": [
            ToolCallLimitMiddleware(tool_name="internet_search", run_limit=10, exit_behavior="continue"),
        ],
        "response_format": NewsList,
    },
    {
        "name": "news-categorizer",
        "description": "集めたニュースを分類して整理する",
        "system_prompt": config.NEWS_CATEGORIZER_PROMPT,
        "model": structured_model,
        "response_format": NewsList,
    },
    {
        "name": "old-news-checker",
        "description": "過去のニュースかどうかを確認する",
        "system_prompt": config.OLD_NEWS_CHECKER_PROMPT,
        "model": structured_model,
        "response_format": NewsList,
    },
    {
        "name": "report-generator",
        "description": "ニュースレポートを作成する",  
        "system_prompt": config.REPORT_GENERATOR_PROMPT,
    },
]
```

`create_deep_agent` に増えた引数は `subagents=subagents` の 1 つだけ。

```python
    agent = create_deep_agent(
```
