## デコレーターとは

興味があれば PEP 318 の原文 [Decorators for Functions and Methods](https://peps.python.org/pep-0318/) を参照。構文の用途と、デコレーターが設計された動機が説明されている。

> The current method for transforming functions and methods (for instance, declaring them as a class or static method) is awkward and can lead to code that is difficult to understand. Ideally, these transformations should be made at the same point in the code where the declaration itself is made. This PEP introduces new syntax for transformations of a function or method declaration.
>
> ---
>
> 日本語訳: 関数やメソッドを変換する現在の方法（たとえばクラスメソッドや静的メソッドとして宣言する方法）は扱いにくく、理解しにくいコードにつながることがある。理想的には、こうした変換は宣言そのものと同じ場所で行うべきである。この PEP は、関数やメソッドの宣言を変換するための新しい構文を導入する。

原文の例によると、

```
@dec2
@dec1
def func(arg1, arg2, ...):
    pass
```

は次と等価である。

```
def func(arg1, arg2, ...):
    pass
func = dec2(dec1(func))
```

## 使い方

### クロージャ（closure）

ここでは簡単に紹介するだけなので、詳しくは [理解Python闭包概念](https://www.cnblogs.com/yssjun/p/9887239.html) を参照。

クロージャの特徴: 関数の内部で定義された関数は、作成されたときの環境を覚えている。外側の関数のスコープで使える変数もそこに含まれる。

```
def outer_function(message):
    msg = [message]
    def inner_function(person):
        msg.append(person)
        print(msg)
    return inner_function

closure = outer_function("Hello, World!")
closure("x")
closure("y")
------------------------------------------
['Hello, World!', 'x']
['Hello, World!', 'x', 'y']
```

#### クロージャとオブジェクト指向

クロージャは簡潔で、関数型プログラミングの重要な要素でもあるが、可読性ではやや劣る。

オブジェクト指向は属性を使って、より複雑な場面にも対応しやすいが、ときに大げさになる。

#### 注意点

**ミュータブル型とイミュータブル型**

参考 [可变与不可变类型](https://www.cnblogs.com/superwuchaofan/p/16562454.html)

> 組み込み関数`id()`は値のメモリアドレスを返す。
>
> ミュータブルなオブジェクトは、`id()`を変えずに値を変更できる。<br>
> 基本データ型のうち、リスト、集合、辞書はミュータブルである。
>
> オブジェクトの値を変更するには新しいオブジェクトを作る必要がある場合、そのオブジェクトはイミュータブルである。<br>
> 基本データ型のうち、数値、文字列、タプルはイミュータブルである。

##### 変数の参照

inner function からは outer function の変数にアクセスでき、ミュータブルな型（リスト、辞書など）は変更できるが、イミュータブルな型（数値、文字列、タプルなど）は変更できない。<br>
自分の理解では、内側の関数は外側の関数の変数が指すアドレスを変えられないが、そのアドレス上で値を変更することはできる。

```
def outer_function(message):
    msg = message
    def inner_function(person):
        msg += person
        print(msg)
    return inner_function

closure = outer_function("Hello, World!")
closure("x")
closure("y")
------------------------------------------
    msg += person
    ^^^
UnboundLocalError: cannot access local variable 'msg' where it is not associated with a value
```

ただし `nonlocal` を使えば、その変数が外側の関数のものだと Python に伝えられる。

```
def outer_function(message):
    msg = message
    def inner_function(person):
        nonlocal msg
        msg += person
        print(msg)
    return inner_function

closure = outer_function("Hello, World!")
closure("x")
closure("y")
------------------------------------------
Hello, World!x
Hello, World!xy
```

##### クロージャの落とし穴

よく知られた例を使う。

```
# この例の意図は、ループごとの i の 2 乗を記録すること
def my_func(*args):
    fs = []
    for i in range(3):
        def func():
            return i * i
        fs.append(func)
    return fs

# この考え方なら、期待される結果は 0 1 4
# しかし実際は 4 4 4
fs1, fs2, fs3 = my_func()
print(fs1())
print(fs2())
print(fs3())
```

ここでブログ記事 [循环变量与闭包](https://suborbit.net/posts/loopvar-and-closure/) を読んだ。その中で次のように説明されている。

> Python で新しいスコープを作るのはモジュール（module）、クラス（class）、関数（def、lambda）だけで、それ以外のコードブロック（`if`、`for`、`while` など）は新しいスコープを作らない。また、Python のクロージャは変数を参照で捕捉するので、最終的な出力が同じ値になることはもう予想できる。

その記事にある他の言語の場合と比べると、Python ではループ変数が使い回され、クロージャはポインタのような形でその変数のアドレスを指して捕捉している、と理解できる。<br>
そのため新しい変数は作られず、古い変数がループのたびに同じアドレス上で変わり続ける。fs に append されたものも、そのアドレスに保存された値の変化に合わせて変わる変数である。<br>
結果として、ループが終わった時点ではすべて 4 になる。

以上の理由から、新しいスコープを作る lambda を使えばよい。

```
def my_func(*args):
    fs = []
    for i in range(3):
        fs.append((lambda x=i: x * x))
    return fs


fs1, fs2, fs3 = my_func()
print(fs1())
print(fs2())
print(fs3())
```

> 返すクロージャでは、ループ変数や後で変わる変数を参照しないこと。

### デコレーター

> デコレーターはクロージャの応用の一つである

例を 1 つ見るのがわかりやすいと思うので、まずコード全体を載せる。

```
from functools import wraps


def the_first(fn):
    @wraps(fn)
    def firstly_wrapped():
        """wrapped in the first function"""
        print("in firstly_wrapped")
        print(fn.__name__)
        print(fn.__doc__)
        return 'here is the first function - ' + fn()

    return firstly_wrapped


def the_second(fn):
    @wraps(fn)
    def second_wrapped():
        """wrapped in the second function"""
        print("in second_wrapped")
        print(fn.__name__)
        print(fn.__doc__)
        return 'here is the second function - ' + fn()

    return second_wrapped


@the_first
@the_second
def hello_world():
    """hello with two decoration"""
    return "Hello World"


print(hello_world())
-------------------------------------------------------------
in firstly_wrapped # firstly_wrapped 内の print の出力
hello_world # firstly_wrapped で出力した fn.__name__
hello with two decoration # firstly_wrapped で出力した fn.__doc__（def の下で """""" に囲まれたテキスト）
in second_wrapped # second_wrapped 内の print の出力
hello_world # second_wrapped で出力した fn.__name__
hello with two decoration # second_wrapped で出力した fn.__doc__
here is the first function - here is the second function - Hello World # hello_world の return
```

まず `hello_world` の部分を見る。

```
@the_first
@the_second
def hello_world():
    """hello with two decoration"""
    return "Hello World"

print(hello_world())
```

2 つのデコレーターは次と等価である。

```
the_first(the_second(hello_world()))
```

実行の流れは `the_first` → `the_second` → `hello_world` になる。

次に `@wraps(fn)` の部分。このデコレーターは `hello_world` が上書きされないようにするためのもので、2 つの `@wraps(fn)` をどちらもコメントアウトすると次のようになる。

```
in firstly_wrapped # firstly_wrapped 内の print の出力
second_wrapped # firstly_wrapped で出力した fn.__name__
wrapped in the second function # firstly_wrapped で出力した fn.__doc__
in second_wrapped # second_wrapped 内の print の出力
hello_world # second_wrapped で出力した fn.__name__
hello with two decoration # second_wrapped で出力した fn.__doc__
here is the first function - here is the second function - Hello World # hello_world の return
```

最初の結果との違いは主に次の部分である。

```
second_wrapped # firstly_wrapped で出力した fn.__name__
wrapped in the second function # firstly_wrapped で出力した fn.__doc__
```

これは、このとき `firstly_wrapped` に渡されているのが `hello_world` ではなく、`hello_world` を上書きした `second_wrapped` だからである。

> `@wraps` デコレーターは、ラップされる関数のメタデータ（関数名、ドキュメント文字列、関数シグネチャなど）を保持する。

`fn` の情報を `firstly_wrapped` にコピーするものと考えればよい。この関数の中に出てくる `fn` は常に `fn` そのものを指し、上書きされない。
