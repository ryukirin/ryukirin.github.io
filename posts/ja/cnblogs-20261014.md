### 第 3 章 Deep Agents の Context Engineering

#### ファイルツール

現行バージョンの Deep Agents にはファイルツールが 7 つある。


| ツール       | 用途                                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `ls`         | ディレクトリ内のファイルとメタ情報（サイズ、更新日時）を一覧表示する                                                      |
| `read_file`  | ファイルの内容を読む。オフセットと件数の上限（`offset` と `limit` 引数）を指定でき、マルチモーダル形式（画像、動画、音声、PDF/PPT）にもネイティブ対応 |
| `write_file` | ファイルを新規作成する、または既存ファイルを丸ごと上書きする                                                              |
| `edit_file`  | 既存ファイルに対して文字列の完全一致置換を行う                                                                            |
| `delete`     | ファイルまたはディレクトリを削除する（**v0.7 で追加**）                                                                   |
| `glob`       | パターンでファイルを検索する（例: `**/*.py`）                                                                             |
| `grep`       | ファイルの内容をリテラル一致で検索する。内容の出力（`output_mode="content"`）と件数の出力（`output_mode="count"`）に対応 |

#### コンテキストの自動管理

- 長いツール結果（デフォルトは 20,000 tokens、`tool_token_limit_before_evict` で変更可）は自動で仮想ファイルシステムに書き込まれる。対話履歴にはファイルパスへの参照と先頭 10 行のプレビューだけが残り、Agent は必要に応じてファイルを読める
- 対話履歴の要約（compact）は、デフォルトではコンテキストウィンドウの 85% を消費した時点で動く。メッセージ履歴を保存したうえで要約を生成してモデルに渡し、コンテキストが失われるのを防ぐ

#### 差し替え可能なストレージバックエンド

**StateBackend（デフォルト）: 一時ストレージ**

LangGraph の Agent State に保存される
- 1 つの対話スレッドの中では保持される
- 対話スレッドが終わると消える
- メイン Agent とサブ Agent でファイルを共有する

**FilesystemBackend: ローカルディスク**

```python
from deepagents.backends import FilesystemBackend

agent = create_deep_agent(
    model=model,
    backend=FilesystemBackend(root_dir=".", virtual_mode=True)
)
```
ローカルのファイルシステムを直接読み書きする
- `root_dir` はアクセスできるルートディレクトリを指定する。相対パスは絶対パスに解決され、`.` はカレントディレクトリを表す（例: カレントディレクトリが D ドライブのルートの場合、`root_dir="."` は `D:\` に解決される）
- `virtual_mode=True` でサンドボックスが有効になり、範囲外への書き込みを防ぐ。`root_dir` だけではここまで強く制限できない
- ファイルの変更は永続的で、元に戻せない

**LocalShellBackend: ローカル Shell 実行**

```python
from deepagents.backends import LocalShellBackend

agent = create_deep_agent(
    model=model,
    backend=LocalShellBackend(root_dir=".", virtual_mode=True, env={"PATH": "/usr/bin:/bin"})
)
```

LocalShellBackend は FilesystemBackend を拡張したもので、execute ツールが加わり、ホストマシン上で Shell コマンドを直接実行できる

- コマンドは `subprocess.run(shell=True)` で実行され、サンドボックスによる隔離は一切ない
- `timeout`（デフォルト 120 秒）、`max_output_bytes`（デフォルト 100,000）、`env` などの引数を指定できる
- `root_dir` はコマンドの作業ディレクトリになるが、コマンドはシステム上の任意のパスにアクセスできる

危険なコマンドを実行するリスクが大きいので、次の対策を取る

- `root_dir` はユーザーのホームディレクトリやリポジトリの上位ディレクトリではなく、専用の一時ワークスペースを指すようにする
- `virtual_mode=True` を明示的に設定し、`env / PATH` を最小限にしてコマンドから見える範囲を狭める
- `.env`、秘密鍵、クラウドの認証情報、本番環境の設定ファイルを Agent がアクセスできるディレクトリに置かない
- `rm`、`mv`、依存関係のインストール、設定変更、ネットワークアクセスなどの高リスク操作には Human-in-the-Loop の承認を入れる
- 信頼できないコードの実行、ユーザーがアップロードしたファイルの処理、外部向けサービスの提供が必要な場合は、`LocalShellBackend` を使わずサンドボックスバックエンドに切り替える

**StoreBackend: セッションをまたいだ永続化**
```python
from langgraph.store.memory import InMemoryStore
from deepagents.backends import StoreBackend

agent = create_deep_agent(
    model=model,
    backend=StoreBackend(
        namespace=lambda rt: (rt.server_info.user.identity,),  # ユーザーごとにデータを分離
    ),
    store=InMemoryStore()  # 開発用。LangSmith にデプロイする場合は省略でき、プラットフォームが自動で用意する
)
```
ファイルは LangGraph の Store に保存される

- スレッドをまたいで永続化され、異なる対話から同じファイルにアクセスできる
- `namespace` 引数でデータの分離を制御する。`lambda rt: (rt.server_info.user.identity,)` はユーザーごとに分離し、データが混ざるのを防ぐ
- 開発時は InMemoryStore を使い、LangSmith にデプロイする場合は `store` 引数を省略する（プラットフォームが自動で設定する）

`namespace` に `rt.server_info.user.identity` を使うと、LangSmith にデプロイした場合は自動で値が入る。ただしローカルで `invoke()` すると `rt.server_info` が `None` になり、そのままアクセスするとエラーになる

```python
namespace=lambda rt: (
    (rt.server_info.user.identity,)
    if rt.server_info else
    ("local-user",)
),
```

**CompositeBackend: 混合ルーティング**

```python
from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from langgraph.store.memory import InMemoryStore

agent = create_deep_agent(
    model=model,
    backend=CompositeBackend(
        default=StateBackend(),            # デフォルト: 一時ストレージ
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
                # LangSmith につながない場合は if rt.server_info else ("local-user",) を追加
            ),
        }
    ),
    store=InMemoryStore()
)
```

- Agent が `/workspace/plan.md` に書き込む → StateBackend（一時）
- Agent が `/memories/preferences.txt` に書き込む → StoreBackend（永続化、ユーザーごとに分離）
- `ls`、`glob`、`grep` はすべてのバックエンドの結果を自動で集約し、パスのプレフィックスは保持される

`/memories/` をルートに指定すると、このフォルダ配下のどのフォルダに書き込んでも StoreBackend にマッチする

```python
import tempfile
from pathlib import Path

from deepagents.backends import CompositeBackend, FilesystemBackend, StateBackend

with tempfile.TemporaryDirectory() as a, tempfile.TemporaryDirectory() as b:
    memories = FilesystemBackend(root_dir=a, virtual_mode=True)
    projects = FilesystemBackend(root_dir=b, virtual_mode=True)
    backend = CompositeBackend(default=StateBackend(), routes={"/memories/": memories, "/memories/projects/": projects})

    for path in ["/memories/user/prefs.md", "/memories/2026/10/notes.md", "/memories/projects/demo/plan.md"]:
        print(path, "->", backend.write(path, "x").error or "ok")

    print("\n/memories/ に対応するディレクトリ A:", sorted(p.relative_to(a).as_posix() for p in Path(a).rglob("*") if p.is_file()))
    print("/memories/projects/ に対応するディレクトリ B:", sorted(p.relative_to(b).as_posix() for p in Path(b).rglob("*") if p.is_file()))
-------------------------------------------------------------------------------
/memories/user/prefs.md -> ok
/memories/2026/10/notes.md -> ok
/memories/projects/demo/plan.md -> ok

/memories/ に対応するディレクトリ A: ['2026/10/notes.md', 'user/prefs.md']
/memories/projects/ に対応するディレクトリ B: ['demo/plan.md']
```

#### カスタムバックエンドとセキュリティポリシー

**宣言的な権限: FilesystemPermission**

```python
from deepagents import create_deep_agent, FilesystemPermission

agent = create_deep_agent(
    model=model,
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
                # LangSmith につながない場合は if rt.server_info else ("local-user",) を追加
            ),
        },
    ),
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/policies/**"],
            mode="deny",           # /policies/ 配下のファイルへの書き込みをすべて禁止
        ),
    ],
)
```
`mode` は 3 種類:
- `allow` 許可
- `deny` 拒否
- `interrupt` 人による承認を待つ。Checkpointer が必要で、ツールの承認と同じ `Command(resume=...)` を使う

権限ルールは最初にマッチしたものが適用されるので、具体的なルールは広いルールより前に書く

**セキュリティポリシー: PolicyWrapper**

インターセプト型のポリシー（レート制限、監査ログ、内容チェック）が必要な場合

方法 1: 既存のバックエンドを継承する

```python
from deepagents.backends.filesystem import FilesystemBackend
from deepagents.backends.protocol import WriteResult, EditResult, DeleteResult

class GuardedBackend(FilesystemBackend):
    def __init__(self, *, deny_prefixes: list[str], **kwargs):
        super().__init__(**kwargs)
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in deny_prefixes]

    def write(self, file_path: str, content: str) -> WriteResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return WriteResult(error=f"書き込みが拒否されました：{file_path}")
        return super().write(file_path, content)

    def edit(self, file_path: str, old_string: str, new_string: str,
             replace_all: bool = False) -> EditResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return EditResult(error=f"編集が拒否されました：{file_path}")
        return super().edit(file_path, old_string, new_string, replace_all)

    def delete(self, file_path: str) -> DeleteResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return DeleteResult(error=f"削除が拒否されました：{file_path}")
        return super().delete(file_path)
```

方法 2: 汎用ラッパー（どのバックエンドにも使える）

```python
from deepagents.backends.protocol import BackendProtocol, WriteResult, EditResult, DeleteResult

class PolicyWrapper(BackendProtocol):
    def __init__(self, inner: BackendProtocol, deny_prefixes: list[str]):
        self.inner = inner
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in deny_prefixes]

    def _deny(self, path: str) -> bool:
        return any(path.startswith(p) for p in self.deny_prefixes)

    def ls(self, path): return self.inner.ls(path)
    def read(self, file_path, offset=0, limit=2000): return self.inner.read(file_path, offset=offset, limit=limit)
    def grep(self, pattern, path=None, glob=None): return self.inner.grep(pattern, path, glob)
    def glob(self, pattern, path="/"): return self.inner.glob(pattern, path)

    def write(self, file_path: str, content: str) -> WriteResult:
        if self._deny(file_path):
            return WriteResult(error=f"書き込みが拒否されました：{file_path}")
        return self.inner.write(file_path, content)

    def edit(self, file_path: str, old_string: str, new_string: str,
             replace_all: bool = False) -> EditResult:
        if self._deny(file_path):
            return EditResult(error=f"編集が拒否されました：{file_path}")
        return self.inner.edit(file_path, old_string, new_string, replace_all)

    def delete(self, file_path: str) -> DeleteResult:
        if self._deny(file_path):
            return DeleteResult(error=f"削除が拒否されました：{file_path}")
        return self.inner.delete(file_path)
```

#### 所感

仮想ファイルシステムは、AI 向けのファイルと人間向けのファイルを分ける仕組みだと感じた。AI 向けのファイルはローカルディスクの容量を使わない。一方で、保存の仕方によっては実行環境に影響が出るため、AI Security が大事になる。Deep Agents には複数のストレージ方式があり、組み合わせも柔軟に選べる。読み書きの権限も定義でき、ストレージバックエンドで独自のセキュリティポリシーを入れたい場合は、既存クラスを継承して各ツールを書き換えることもできる。
