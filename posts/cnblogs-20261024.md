### 第八章 长期记忆 — 让 Agent 拥有跨对话的记忆

#### Memory 的工作原理

Agent 以文件形式读写记忆，你用 Backend 控制这些文件存储在哪里

1. 准备存储与文件：配置 Backend 和 Store，并预置需要加载的记忆文件
2. 加载记忆：
   1. `memory=` 指定**已有文件**的路径，内容进入系统提示词
   2. `skills=` 指定包含 Skill 子目录的目录，先注入元数据，正文由 Agent 按需读取
3. 更新记忆（可选）：通过提示词约定何时写入、写到哪个文件，再由 Agent 调用 `edit_file` 等工具更新，供后续对话使用

#### Agent 的两种“记忆”

**短期记忆：Thread-scoped**

默认的 StateBackend 将文件存在 LangGraph 的 Agent State 中。这是一种短期记忆

- 同一个对话线程（thread）内持久化
- 多轮对话不丢失（通过 Checkpointer 机制）
- 按 thread_id 隔离
  - 新线程不能读取旧线程的 State 文件
  - 只要 Checkpointer 仍保存旧线程状态，返回旧线程仍可读取

[Checkpointer详细](#checkpointer-短期记忆的基础)

**长期记忆：Cross-thread**

存储需要在多个对话之间共享的信息

- 用户的偏好设置
- 项目的背景知识
- 累积的研究成果
- Agent 从反馈中学到的改进指令

#### Checkpointer：短期记忆的基础

可以对照聊天软件来理解：一个线程是一个聊天窗口，发一条消息是一次 invoke，新建聊天就是换一个新的 thread_id

```
线程 thread_id="a1"            ← 一段对话（一个聊天窗口）
├── 第 1 轮 invoke("我叫张三")   ← 一次运行
│     └── 模型 → 工具 → 模型 …   ← 多个步骤，每步结束后 Checkpointer 存一个快照
├── 第 2 轮 invoke("我叫什么？")
│     └── 先从 a1 最新的快照恢复 State，再继续
线程 thread_id="a2"            ← 另一段对话，有自己的 State，从空白开始
```

```python
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()

agent = create_deep_agent(
    model=model,
    checkpointer=checkpointer,
)

# 同一个 thread_id 内，Agent 记得之前的对话
config = {"configurable": {"thread_id": "conversation-001"}}
agent.invoke({"messages": [{"role": "user", "content": "我叫张三"}]}, config=config)
agent.invoke({"messages": [{"role": "user", "content": "我叫什么名字？"}]}, config=config)
# Agent 能回答"你叫张三"

# 换一个 thread_id，Agent 不记得了
config2 = {"configurable": {"thread_id": "conversation-002"}}
agent.invoke({"messages": [{"role": "user", "content": "我叫什么名字？"}]}, config=config2)
# Agent 不知道你是谁
```

Checkpointer 的工作原理：

- 每次 Agent 执行完一步，自动保存当前状态（消息历史、文件系统状态，以及启用 Todo 后的任务清单等）
- 下次调用时，如果 thread_id 相同，自动恢复上次的状态
- 开发用 MemorySaver（内存，重启丢失），生产用 PostgresSaver（数据库，持久化）

| 配置                                | 结果                                                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 不配 Checkpointer                   | 每次 invoke 都是独立的，没有"线程"这个概念，多轮之间什么都不保留                                             |
| 配了 Checkpointer，但没传 thread_id | 直接报错：ValueError: Checkpointer requires one or more of the following 'configurable' keys: thread_id, ... |
| 配了 Checkpointer，并传 thread_id   | 同一个 thread_id 的多轮共用一份 State                                                                        |

**短期记忆的管理策略**


| 策略              | 做法                                                                          | 适用场景                             |
| ----------------- | ----------------------------------------------------------------------------- | ------------------------------------ |
| Trim（裁剪）      | 只保留最近 N 条消息，丢弃更早的，如果要自定义可以通过`@before_model` 中间件   | 简单粗暴，适合不需要历史上下文的场景 |
| Delete（删除）    | 用 RemoveMessage 精确删除特定消息                                             | 需要选择性清理（如删除敏感信息）     |
| Summarize（总结） | 用 LLM 将旧消息压缩为摘要，已自动内置 `SummarizationMiddleware`，支持同名覆盖 | 需要保留历史语义，是最推荐的方式     |

自定义裁剪逻辑

```python
from langchain.messages import RemoveMessage
from langgraph.graph.message import REMOVE_ALL_MESSAGES
from langchain.agents import AgentState
from langchain.agents.middleware import before_model
from langgraph.runtime import Runtime

@before_model
def trim_messages(state: AgentState, runtime: Runtime) -> dict | None:
    """只保留最近几条消息，防止上下文溢出。"""
    messages = state["messages"]
    if len(messages) <= 3:
        return None  # 不需要裁剪

    first_msg = messages[0]  # 保留第一条（通常是系统消息）
    recent = messages[-3:]   # 保留最近 3 条
    return {
        "messages": [
            RemoveMessage(id=REMOVE_ALL_MESSAGES),
            first_msg,
            *recent,
        ]
    }

# 在 create_agent 或 create_deep_agent 中通过 middleware 参数添加
agent = create_deep_agent(
    model=model,
    middleware=[trim_messages],
)
```

**进阶：自定义 AgentState**

在 Deep Agents 默认用的是 DeepAgentState，在 LangChain 中默认用的是 AgentState

|                     | AgentState                                                                                 | DeepAgentState                                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| messages 的保存方式 | add_messages：每个检查点都把当时的完整消息列表复制一份，历史消息在每个检查点里都重复存一次 | DeltaChannel：检查点里不放完整列表，每一步只记下新增的那条，读取时从头把这些增量拼起来。每隔大约 50 步会存一次完整快照，读取时不用每次都从第一条开始拼 |
| 检查点体积          | 随步数平方增长                                                                             | 随步数线性增长                                                                                                                                         |
| 用在哪              | create_agent 的 state_schema，以及自定义中间件的 state_schema                              | create_deep_agent 的 state_schema                                                                                                                      |

这两个都默认有三个字段
- `messages`：历史消息
- `jump_to`：中间件内部用来控制跳转的字段，私有，外部看不到
- `structured_response`：结构化输出

每个中间件都可以继承默认 State，加上自己的字段。创建 Agent 时，这些结构合并成最终的 State

| 中间件               | 结构类            | 加的字段                       |
| -------------------- | ----------------- | ------------------------------ |
| FilesystemMiddleware | `FilesystemState` | `files`（StateBackend 的文件） |
| TodoListMiddleware   | `PlanningState`   | `todos`                        |
| SkillsMiddleware     | `SkillsState`     | `skills_metadata` 等           |
| MemoryMiddleware     | `MemoryState`     | `memory_contents`              |

字段上的标注决定了外部能不能看到它：

- `OmitFromOutput`：不出现在 invoke 的返回值里
- `PrivateStateAttr`：只给中间件内部用

Checkpointer 每一步保存的，就是这整份 State

自定义的时候是往默认 State 里追加新的字段，同名时覆盖

```python
# 仅保留关键代码，输出和构建 write_todos 省略
class MyState(DeepAgentState):
    """在 Deep Agents 默认 State 上加两个新字段，并重新声明一个同名字段"""

    # 不同名，没有合并规则：更新时新值覆盖旧值
    note: NotRequired[str]

    # 不同名，operator.add：更新时追加
    tags: NotRequired[Annotated[list[str], operator.add]]

    # 同名（TodoListMiddleware 已有），改成更新时追加
    todos: NotRequired[Annotated[list, operator.add]]
```

工具可以通过 ToolRuntime 读写这些自定义状态字段

```python
@tool
def get_note(runtime: ToolRuntime) -> str:
    """读取当前的备注和标签。"""

    # runtime.state 是读状态
    return f"备注：{runtime.state.get('note', '（无）')}，标签：{runtime.state.get('tags', [])}"

@tool
def update_note(new_note: str, runtime: ToolRuntime) -> Command:
    """把备注改成 new_note。"""

    # Command(update={...}) 写状态
    return Command(update={
        "note": new_note,   # 整体替换
        "messages": [ToolMessage(f"备注已改为 {new_note}", tool_call_id=runtime.tool_call_id)],
    })

@tool
def add_tag(tag: str, runtime: ToolRuntime) -> Command:
    """给当前对话加一个标签。"""

    # Command(update={...}) 写状态
    return Command(update={
        # operator.add 会接到旧列表后面，只传新增的部分
        "tags": [tag],
        "messages": [ToolMessage(f"已添加标签 {tag}", tool_call_id=runtime.tool_call_id)],
    })

agent = create_deep_agent(model=model, tools=[get_note, update_note, add_tag],
                          state_schema=MyState, checkpointer=InMemorySaver())
```

调用时传入初始值 `note="a"`、`tags=["x"]`，剧本模型依次执行：读、改 `note`、加 `tag`、再读
运行结果

#### CompositeBackend：长期记忆的核心方案

**运行时身份与 namespace**

`StoreBackend` 通过 `namespace` 区分不同用户、Agent 或组织的数据
部署到 LangSmith / LangGraph Server 时 `rt.server_info` 可以提供 `assistant_id` 和登录用户信息
本地运行或者自托管的时候需要加一个自定义字段

```python
def assistant_namespace(rt):
    if rt.server_info:
        return (rt.server_info.assistant_id,)
    return ("local-agent",)


def user_namespace(rt):
    if rt.server_info and rt.server_info.user:
        return (rt.server_info.user.identity,)
    user_id = getattr(rt.context, "user_id", "local-user")
    return (user_id,)


def org_namespace(rt):
    org_id = getattr(rt.context, "org_id", "default-org")
    return (org_id,)
```

**Agent 级记忆（Agent-scoped）**

在所有用户间共享，一个 Agent 用一份记忆，使用上边的 `assistant_namespace()`

```python
from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from dataclasses import dataclass

@dataclass(frozen=True)
class MemoryContext:
    user_id: str = "local-user"
    org_id: str = "default-org"

agent = create_deep_agent(
    model="google_genai:gemini-3.5-flash",
    context_schema=MemoryContext,
    memory=["/memories/AGENTS.md"],          # 启动时自动加载的记忆文件
    skills=["/skills/"],
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(
              # 以 local-agent 为例，存到 local-agent 的 memories 抽屉里
                namespace=lambda rt: (*assistant_namespace(rt), "memories"),
            ),
            "/skills/": StoreBackend(
                namespace=lambda rt: (*assistant_namespace(rt), "skills"),
            ),
        },
    ),
)
```

**跨对话访问**

```python
from dataclasses import dataclass
from uuid import uuid4

from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from deepagents.backends.utils import create_file_data
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore


@dataclass
class UserContext:
    user_id: str


store = InMemoryStore()
# 测试用户 user-123
user = UserContext(user_id="user-123")
# user-123 的 memories中
namespace = (user.user_id, "memories")
# Agent 会自动加上路由前缀
key = "/preferences.md" 
# 具体文件名
memory_path = "/memories/preferences.md"

# 先创建文件；CompositeBackend 会去掉 /memories/ 路由前缀
# 这是新 Store 的首次初始化
# 已有 Store 应先检查文件，避免覆盖旧偏好
if store.get(namespace, key) is None:
    store.put(namespace, key, create_file_data("# 用户偏好\n暂无记录。"))

agent = create_deep_agent(
    model=model,
    context_schema=UserContext,
    store=store,
    checkpointer=InMemorySaver(),
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.context.user_id, "memories"),
            ),
        },
    ),
    memory=[memory_path],
    system_prompt=(
        f"当用户明确要求记住偏好时，先读取 {memory_path}，再用 edit_file 更新它。"
        "逐字保存用户给出的偏好条目，保留其他已有偏好，不要另建偏好文件。"
        "只有工具写入成功后，才告知用户已记住。"
    ),
)

# 对话 1：保存用户偏好
agent.invoke(
    {"messages": [{"role": "user", "content": "记住我的偏好：代码注释用中文，变量名用英文"}]},
    context=user,
    config={"configurable": {"thread_id": str(uuid4())}},
)

# 从 Store 核对写入结果，不能只看模型是否回复“已记住”。
saved = store.get(namespace, "/preferences.md")
assert saved is not None, "偏好文件未保存，请检查工具调用"
content = saved.value["content"]
print("保存后的偏好：", content)
assert "代码注释用中文" in content and "变量名用英文" in content, "偏好未按约定写入，请检查 trace"

# 对话 2（全新的对话！）：读取之前保存的偏好
result = agent.invoke(
    {"messages": [{"role": "user", "content": "帮我写一个排序函数"}]},
    context=user,
    config={"configurable": {"thread_id": str(uuid4())}},
)
print(result["messages"][-1].content)
```

每次重新运行整段代码都会创建新的 `InMemoryStore`，它只在当前进程中保留数据
跨线程需复用 Store，跨进程或重启后保留则需要本章后面的持久化 Store

#### 使用场景

- 用户偏好记忆：用用户级的命名空间区分每个用户的偏好
- 自我改进的 Agent：根据用户反馈更新自己的指令
- 知识库累积：跨多次对话逐渐构建知识库
- 研究项目持续推进：Agent 启动时加载所有研究文件，每次对话结束后更新进度。多个 memory 路径让研究可以跨对话持续推进

#### 高级用法

**记忆的六个维度**

| 维度     | 核心问题       | 选项                                                         |
| -------- | -------------- | ------------------------------------------------------------ |
| 持续时间 | 保留多久？     | 短期（单次对话）/ 长期（跨对话）                             |
| 信息类型 | 记什么？       | 情景记忆（过去经历）/ 程序性记忆（Skills）/ 语义记忆（事实） |
| 作用域   | 谁能看？       | 用户级 / Agent 级 / 组织级                                   |
| 更新策略 | 何时写入？     | 对话中（默认）/ 对话间（后台整合）                           |
| 检索方式 | 如何读取？     | 启动加载（memory=）/ 按需读取（Skills）                      |
| 权限控制 | Agent 能写吗？ | 读写（默认）/ 只读（共享策略）                               |

**组织级记忆（Organization-level）**

组织级记忆跨所有用户和 Agent 共享，通常设为只读以防止注入攻击
使用上边的 `org_namespace()`

**情景记忆（Episodic Memory）**

情景记忆存储过去的完整经历，让 Agent 能回忆“如何解决问题”而不仅是“学到了什么”
Deep Agents 的 Checkpointer 天然支持情景记忆，要让过去的对话变得可搜索，可以包装一个搜索工具

课程和官方文档的原示例里，`query` 没有被用到，不管搜什么返回的都一样。而且用的是 `get_history`，它返回的是检查点列表，同一段对话会在多个检查点里重复出现。下面改成按关键词做字面匹配，和 Deep Agents 自带的 grep 工具一样

```python
from langchain.tools import tool, ToolRuntime
from langgraph_sdk import get_client

client = get_client(url="<DEPLOYMENT_URL>")


def current_user_id(runtime: ToolRuntime) -> str:
    if runtime.server_info and runtime.server_info.user:
        return runtime.server_info.user.identity
    user_id = getattr(runtime.context, "user_id", None)
    if user_id:
        return user_id
    raise ValueError("需要在 server_info 或 runtime.context 中提供 user_id")


@tool
async def search_past_conversations(query: str, runtime: ToolRuntime) -> str:
    """在该用户过去的对话中查找包含关键词 query 的消息。按字面匹配，找不到时换用同义词、英文或更短的关键词再搜。"""
    user_id = current_user_id(runtime)
    current_thread = runtime.config.get("configurable", {}).get("thread_id")
    threads = await client.threads.search(
        metadata={"user_id": user_id},
        limit=5,
        sort_by="updated_at",  # 接口文档没有规定默认顺序，显式指定
        sort_order="desc",
    )
    keyword = query.strip().lower()
    if not keyword:
        return "query 不能为空，请传入要查找的关键词后重新调用。"
    hits = []
    for thread in threads:
        if thread["thread_id"] == current_thread:
            # 跳过正在进行的对话
            continue
        # get_state 只返回当前状态，不会像 get_history 那样重复
        state = await client.threads.get_state(thread_id=thread["thread_id"])
        for message in state["values"].get("messages", []):
            content = str(message.get("content", ""))
            if keyword in content.lower():
                hits.append(f"[{thread['thread_id']}] {message.get('type')}: {content[:300]}")
    return "\n".join(hits[:10]) or f"没有找到包含“{query}”的过去对话。"
```

几点说明

- `threads.search()` 只能按元数据、状态等条件筛选线程，不接受文本查询，所以在客户端匹配消息正文
- 搜索词由模型生成，只能找到用词一致的内容，比如搜“报错”找不到只写了“KeyError”的对话，所以在工具说明里提示模型换词再搜
- 线程 `metadata` 里的 `user_id` 是应用创建线程时自己写进去的，服务器不会自动加，没写的话一个线程都搜不到
- 当前线程通常是最近更新的那个，也算在 5 个里面，所以一般只搜到 4 个过去的线程
- 需要语义搜索时，可以把对话摘要写进启用了语义检索的 Store（在 `langgraph.json` 里配置 `store.index`），再用 `client.store.search_items(namespace, query=query)` 查询

**后台记忆整合（Background Consolidation）**

默认情况下 Agent 在对话中实时写入记忆（热路径）。另一种模式是在对话间后台处理——部署一个独立的“整合 Agent”来审查最近对话、提取关键事实、合并到记忆存储中
代码详见
[整合 Agent 示例](https://datawhalechina.github.io/deepagents-in-action/chapters/ch08-long-term-memory/#%E5%90%8E%E5%8F%B0%E8%AE%B0%E5%BF%86%E6%95%B4%E5%90%88background-consolidation)
`search_recent_conversations` 的 `query: str` 不需要

**并发写入**

对 Agent 级或组织级记忆，考虑用后台整合来序列化写入，或将记忆按主题拆分成独立文件以减少冲突

- 按主题拆文件：把 `/memories/preferences.md`、`/memories/project/tech-stack.md`、`/memories/research/sources.md` 拆开，减少多个线程同时改同一文件的概率
- 追加式记录，再后台合并：对话中先写入 `/memories/events/2026-xx-xx-thread-id.md` 这类追加日志，后台整合 Agent 定期去重、合并到稳定记忆文件
- 共享记忆只让后台任务写入：Agent 级、组织级记忆尽量只读，普通对话只提交候选更新，由后台整合任务串行审核后写入
- 敏感记忆加审批：涉及组织策略、安全规则、长期偏好覆盖时，用 Permissions 或 Human-in-the-Loop 阻止未经确认的直接覆盖

### 第九章 Human-in-the-Loop — 构建安全的人机协作流程

Human-in-the-Loop（HITL）：Agent 在执行特定操作前暂停，等待人类审批、修改、拒绝或直接响应，然后再继续执行

#### `interrupt_on` 配置

```python
from deepagents import create_deep_agent
from langgraph.checkpoint.memory import MemorySaver

# 工具和模型定义已省略

# Checkpointer 是 HITL 的必要条件
checkpointer = MemorySaver()

agent = create_deep_agent(
    model=model,
    tools=[delete_file, read_file, send_email],
    interrupt_on={
        # allowed_decisions 指定可供选择的操作
        # 所有操作为 approve / edit / reject / respond
        "delete_file": {"allowed_decisions": ["approve", "edit", "reject"]},
        "read_file": False,    # 无需中断
        "send_email": {"allowed_decisions": ["approve", "reject"]},  # 只能审批或拒绝，不能修改
    },
    checkpointer=checkpointer,  # 必须配置！
)
```

| 决策    | 含义                                                      | 场景                          |
| ------- | --------------------------------------------------------- | ----------------------------- |
| approve | 批准执行，使用 Agent 提出的原始参数                       | “确认删除这个文件”            |
| edit    | 修改参数后执行                                            | “收件人改一下再发”            |
| reject  | 跳过此次工具调用，并把拒绝原因反馈给 Agent                | “不要删除，取消”              |
| respond | 不执行工具，把人的 message 当作一次成功的合成工具结果返回 | `ask_user` 这类“询问用户”工具 |

子 Agent 可以有独立的 `interrupt_on` 配置，覆盖主 Agent 的设置
如果子 Agent 要进行敏感操作的时候可以加上中断询问

#### 条件中断：只拦截真正危险的调用

```python
from deepagents import create_deep_agent
from langchain.agents.middleware import ToolCallRequest
from langgraph.checkpoint.memory import MemorySaver


def writes_outside_workspace(request: ToolCallRequest) -> bool:
    """只有写入工作区外的路径时才暂停。"""
    path = request.tool_call["args"].get("file_path", "")
    return not path.startswith("/workspace/")


agent = create_deep_agent(
    model=model,
    interrupt_on={
        "write_file": {
            "allowed_decisions": ["approve", "edit", "reject"],
            # 返回 True 才暂停，False 执行
            "when": writes_outside_workspace,
        },
    },
    checkpointer=MemorySaver(),
)
```

#### 中断和恢复

当 agent 一次运行中调用了设置中断的工具，执行中断，返回中断信息
用户参照信息做出判断之后通过 thread_id 恢复运行

```python
import uuid
from langgraph.types import Command

# 创建一个 thread_id（恢复时必须使用同一个）
config = {"configurable": {"thread_id": str(uuid.uuid4())}}

# Step 1: 发起请求
result = agent.invoke(
    {"messages": [{"role": "user", "content": "删除 temp.txt 文件"}]},
    config=config,
    version="v2",
)

# Step 2: 检查是否中断
if result.interrupts:
    interrupt_value = result.interrupts[0].value
    action_requests = interrupt_value["action_requests"]
    review_configs = interrupt_value["review_configs"]
    config_map = {cfg["action_name"]: cfg for cfg in review_configs}

    # 展示给用户
    for action in action_requests:
        review_config = config_map[action["name"]]
        args = action.get("arguments", action.get("args", {}))
        print(f"工具: {action['name']}")
        print(f"参数: {args}")
        print(f"可选决策: {review_config['allowed_decisions']}")

    # Step 3: 用户做出决策
    # message 可以自己定义好的（拒绝时的 message）也可以是用户输入
    decisions = [
        {"type": "approve"}  # 用户批准删除
    ]
    # decisions = [{
    #     "type": "reject",
    #     "message": "用户拒绝删除该文件。不要再次尝试删除，请询问是否改为归档文件。",
    # }]

    # Step 4: 恢复执行（必须用相同的 config！）
    result = agent.invoke(
        Command(resume={"decisions": decisions}),
        config=config,     # 同一个 thread_id
        version="v2",
    )

# 获取最终结果
print(result.value["messages"][-1].content)
```

当用户返回 `reject` 时，Deep Agents 会跳过该工具调用，并把拒绝反馈返回给 Agent
如果是敏感工具（比如删除）此时建议明确要求不要再请求删除了，改用其它操作

#### 多个工具调用的中断处理

```python
# 用户请求："删除 temp.txt 并发邮件通知 admin"
result = agent.invoke(
    {"messages": [{"role": "user", "content": "删除 temp.txt 并发邮件通知 admin@example.com"}]},
    config=config,
    version="v2",
)

if result.interrupts:
    action_requests = result.interrupts[0].value["action_requests"]
    # action_requests[0] = delete_file(path="temp.txt")
    # action_requests[1] = send_email(to="admin@example.com", ...)

    # 按顺序提供决策
    decisions = [
        {"type": "approve"},  # 批准删除
        {
            "type": "reject",
            "message": "用户拒绝发送邮件。不要重试这次发送动作。",
        },
    ]

    result = agent.invoke(
        Command(resume={"decisions": decisions}),
        config=config,
        version="v2",
    )
```
决策数量和顺序必须匹配，`decisions` 要和 `action_requests` 一一对应，顺序不能乱

#### 根据风险等级推荐的中断操作

| 风险等级   | 工具类型                   | 配置                      | 理由                                                      |
| ---------- | -------------------------- | ------------------------- | --------------------------------------------------------- |
| 高风险     | 删除、覆盖写入、发送、部署 | `approve`/`edit`/`reject` | 操作不可逆或影响外部系统，避免 `respond` 被误当成成功结果 |
| 中风险     | 写入、外部调用             | `approve`/`reject`        | 可审批但不需要修改参数                                    |
| 低风险     | 读取、搜索、列表           | `False`                   | 只读操作，安全无副作用                                    |
| 人工输入型 | 询问偏好、补充缺失信息     | `respond`                 | 工具本来就是让人回答，人的 `message` 会成为成功工具结果   |

#### 文件系统的 `mode="interrupt"`

`write_file`、`edit_file` 和 `delete` 在命中 `mode="interrupt"` 的权限规则时，Deep Agents 会抛出和普通工具审批相同格式的 HITL 中断

```python
agent = create_deep_agent(
    model=model,
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/secrets/**"],
            mode="interrupt",
        ),
    ],
    checkpointer=MemorySaver(),
)
# 恢复方式和普通工具一致
```

### 按用户划分 namespace

| --------------------------- | ------------------- | ---------------------------------------------------------- |

用户由 `identity.py` 的 `user_namespace` 决定，写法和上文用户级记忆里的 `user_namespace` 相同：

```python
# 暂时全部以 local-user 作为用户身份
def user_namespace(rt):
    if rt.server_info and rt.server_info.user:
        return (rt.server_info.user.identity,)
    user_id = getattr(rt.context, "user_id", "local-user")
    return (user_id,)
```

`context_schema` 用的 `MemoryContext` 写在 `memory_model.py`：

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class MemoryContext:
```

### 写入前人工审批

需要审批的路径由 `agent.py` 的 `protected_path` 判断：

```python
def protected_path(request):
    """定义需要审批操作的路径"""
    path = request.tool_call["args"].get("file_path", "")
    try:
        path = validate_path(path)
    except ValueError:
        return False
    return path.startswith(("/history/", "/report/"))
```

- `interrupt_on` 给 `write_file`、`edit_file`、`delete` 都配了 `when=protected_path`，目标在 `/history/` 或 `/report/` 下时才暂停。写入其他路径（包括 `/memories/`）不暂停
- `protected_path` 先用 `validate_path` 规范化路径，规范化失败时返回 `False`，不暂停
- `allowed_decisions` 只允许 `approve` 和 `reject`
- 子 Agent 里的写入调用同样会暂停
- 恢复执行需要同一个 `thread_id`，所以加了 Checkpointer `MemorySaver`，每次运行用 `uuid4` 生成新的 `thread_id`

暂停时由 `ask_user.py` 的 `ask_decision` 从命令行读取决策：

```python
import json

def ask_decision(action, allowed):
    name = action["name"]
    args = action.get("arguments", action.get("args", {}))
    print(f"\n工具: {name}\n参数: {json.dumps(args, ensure_ascii=False)}\n可选决策: {', '.join(allowed)}")
    while True:                                    # 输入不在允许范围内就重新输入
        choice = input("请输入决策: ").strip()
        if choice in allowed:
            break
        print(f"只能输入 {', '.join(allowed)} 之一")

    if choice == "approve":
        return {"type": "approve"}
    if choice == "edit":                           # 逐个参数询问，直接回车保留原值
        new_args = {}
        for key, value in args.items():
            text = input(f"  {key}（直接回车保留 {value!r}）: ").strip()
            new_args[key] = text if text else value
        return {"type": "edit", "edited_action": {"name": name, "args": new_args}}
    if choice == "reject":                         # 原因可留空，留空时用中间件的默认反馈
        decision = {"type": "reject"}
        reason = input("拒绝原因（可留空）: ").strip()
        if reason:
            decision["message"] = reason
        return decision
    return {"type": "respond", "message": input("回答: ").strip()}
```

- 输入不在 `allowed_decisions` 里时要求重新输入
- `reject` 之后可以输入拒绝原因，原因作为 `message` 返回给模型。留空时用中间件的默认反馈
- `edit` 和 `respond` 的分支现在用不到，`allowed_decisions` 里没有这两项

### Agent

`agent.py` 中创建和运行 Agent 的部分：

```python

    store.setup()  # 首次运行时建表，之后再调用不会重复建

    # 创建线程号 用来中断恢复
    configurable = {"configurable": {"thread_id": str(uuid.uuid4())}}

    agent = create_deep_agent(
        model=model,
        # 定义工具
        tools=[internet_search, get_current_time],
        # 定义系统提示词
        system_prompt=config.SYSTEM_PROMPT,
        # 显式定义中间件
        middleware=[TodoListMiddleware()],
        # 自定义上下文
        context_schema=MemoryContext,
        # 定义记忆文件路径
        memory=["/memories/preferences.md"],
        # 使用 SqliteStore 作为持久化存储
        store=store,
        # 定义后端存储 使用 CompositeBackend 组合多种后端
        backend=CompositeBackend(
            default=StateBackend(),            # 默认：临时存储
            # 路由
            routes={
                "/history/": StoreBackend(
                    namespace=lambda rt: (*user_namespace(rt), "history"),
                ),
                "/memories/": StoreBackend(
                    namespace=lambda rt: (*user_namespace(rt), "memories"),
                ),
                "/report/": StoreBackend(
                    namespace=lambda rt: (*user_namespace(rt), "report"),
                ),
                "/skills/": FilesystemBackend(root_dir="skills", virtual_mode=True),
            }
        ),
        # 将 history、report 目录下的文件写入权限限制为中断模式，防止误操作
        interrupt_on={
            "write_file": {
                "allowed_decisions": ["approve", "reject"], 
                "when": protected_path
            }, 
            "edit_file": {
                "allowed_decisions": ["approve", "reject"], 
                "when": protected_path
            }, 
            "delete": {
                "allowed_decisions": ["approve", "reject"], 
                "when": protected_path
            },
        },
        # 定义权限
        permissions=[
            # 将 skills 只读
            FilesystemPermission(
                operations=["write"],
                paths=["/skills/**"],
                mode="deny",
            ),
        ],
        # 因为要做中断恢复 所以要定义 checkpointer 获取线程 ID
        checkpointer=MemorySaver(),
        # 定义子 Agent 列表
        subagents=subagents,
    )

    result = agent.invoke(
        {"messages": [{"role": "user", "content": config.USER_PROMPT}]},
        config=configurable,
        version="v2",
    )

    while result.interrupts:
        interrupt_value = result.interrupts[0].value
        action_requests = interrupt_value["action_requests"]
        review_configs = interrupt_value["review_configs"]
        config_map = {cfg["action_name"]: cfg for cfg in review_configs}

        # 按顺序提供决策
        decisions = []
        for action in action_requests:
            review_config = config_map[action["name"]]
            args = action.get("arguments", action.get("args", {}))
            decisions.append(ask_decision(action, review_config["allowed_decisions"]))

        result = agent.invoke(
            Command(resume={"decisions": decisions}),
            config=configurable,
            version="v2",
        )

print(result.value["messages"][-1].content)
```

- `create_deep_agent` 新加了 `context_schema`、`memory`、`store`、`interrupt_on`、`checkpointer`。`/report/` 的路由从 `FilesystemBackend` 换成了 `StoreBackend`，新加了 `/memories/` 的路由
- `invoke` 加了 `version="v2"`，用 `result.interrupts` 判断是否暂停。暂停时用 `Command(resume={"decisions": decisions})` 和同一个 `configurable` 恢复，直到没有中断
- `MemorySaver` 只把中断状态存在进程内存里。暂停时退出程序，这次运行无法恢复
- 恢复循环只处理 `result.interrupts` 中的第一个中断。多个子 Agent 并行写入、同时产生多个中断时，LangGraph 要求按中断 ID 分别提供恢复值，现在的写法会报错
