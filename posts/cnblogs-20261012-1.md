## 试错记录

### 安装环境

背景：本机一开始只有Windows系统，并且一开始没想安装Ubuntu

问题：数据库配置一直报错

原因：项目 `.env` 中 `SEEKDB_EMBED=true`，使用 SeekDB 嵌入模式。`pyseekdb` 依赖原生库 `pylibseekdb`，`uv.lock` 中 `pylibseekdb` 的安装条件如下。

```text
(platform_machine == 'arm64' and sys_platform == 'darwin') or sys_platform == 'linux'
```

`pylibseekdb` 1.4.0.post1 只有 macOS arm64 和 Linux（x86_64、aarch64）的安装包，Windows 上不会安装。

解决方法：改在 WSL2 的 Ubuntu 中运行。

1. 打开 PowerShell，执行 `wsl --install`，完成后重启 Windows。
2. 进入 Ubuntu，创建 Linux 用户。
3. 使用以下命令访问D盘（`cd D:\...` 会报 `No such file or directory`）

   ```bash
   cd "/mnt/d/资料/资料/公司/个人/deepagent/research_deepagent"
   ```

### 后端无法连接

背景：在 Ubuntu 中运行 `agentseek dev` 时报错。

问题：

- 前端报 `ConnectionError: Unable to connect to LangGraph server. ... Failed to fetch`。
- `agentseek doctor --live` 中前端（5174）正常，后端报 `fail langgraph: http://127.0.0.1:2024/health is not reachable.`。
- 后端日志出现 `Application startup complete.`，也能响应 `/docs`，随后自动关闭，最后一行如下。

  ```text
  Timed out waiting for 'http://localhost:2024' to become ready: <urlopen error [Errno 111] Connection refused>
  ```

- 后端连通后，发送消息报 `OpenAIConnectionError: Connection error.`，LangSmith 上报也报 `ProxyError`（连接 `127.0.0.1:7890` 被拒绝）。

原因：`127.0.0.1:7890` 不可用，经过代理的请求全部失败。

- `agentseek-api dev` 启动后用 `urllib.request.urlopen` 轮询 `http://localhost:2024/ok` 和 `/health`，判断后端是否就绪（`agentseek_api/cli.py` 的 `_wait_for_dev_server_ready`）。`urllib` 会读取 `HTTP_PROXY`，没有设置 `NO_PROXY` 时，访问 `localhost` 的请求也发往代理。轮询超时后启动器关闭后端，2024 端口因此连不上。
- 模型 API 和 LangSmith 的请求同样经过代理。用 curl 对比，经过代理访问 `https://api.openai.com/v1/models` 返回 `HTTP 000`，加 `--noproxy '*'` 直连返回 `HTTP 401`（请求未带 API Key，401 说明网络已连通）。

解决方法：在运行 `agentseek dev` 的同一个终端中清除代理，并让本机地址不走代理。

```bash
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY http_proxy https_proxy all_proxy
export NO_PROXY="localhost,127.0.0.1,::1"
export no_proxy="$NO_PROXY"
agentseek dev
```

之后 `agentseek doctor --live` 中 `langgraph` 和 `frontend` 两项都显示 `ok`。需要代理时，把代理地址换成实际可用的地址，并保留 `NO_PROXY`。
