## Notes - Chapter 4 Building Classic Agent Paradigms

### Three representative architecture paradigms

- ReAct: think first, then act, then observe the result to decide the next action, all inside a loop
- Plan-and-Solve: make a plan first, then execute it step by step
- Reflection: improve the result through reflection

#### Limitations of existing frameworks

- Highly abstracted: the logic is packed into a shell and only external interfaces are left to the user, so you can't really understand how it runs
- Frameworks that are still unstable are prone to breaking changes
- For scenarios that need heavy customization, building one by hand is more direct

### ReAct

- Thought: think
- Action: decide which action to take
- Observation: execute the action and provide the result

Use cases

- Tasks that need external knowledge
- Tasks that need precise calculation
- Tasks that need to interact with APIs

#### Strengths

- The thinking process is observable and highly transparent, which makes it easy to see what to improve
- Dynamic planning: it can change the plan (the next step) based on results

#### Limitations

- Depends on the LLM's capability
- Long execution time and high cost
- Depends on the prompt
- Prone to getting stuck in local optima, has no long-term planning, and may go down a rabbit hole

### Plan-and-Solve

Make a plan first, then execute

The `Planner` generates the plan, and the `Executor` executes the tasks and manages state

So the executor needs to keep the full plan, the result of each step, and the current progress

Sample prompt

```python
EXECUTOR_PROMPT_TEMPLATE = """
You are a top AI execution expert. Your task is to strictly follow the given plan and solve the problem step by step.
You will receive the original question, the complete plan, and the steps and results completed so far.
Please focus on solving the "current step" and only output the final answer for that step, without any additional explanations or dialogue.

# Original Question:
{question}

# Complete Plan:
{plan}

# Historical Steps and Results:
{history}

# Current Step:
{current_step}

Please only output the answer for the "current step":
"""
```

#### Limitations

The initial plan matters a lot. If the plan is wrong, everything after it stays wrong

### Reflection

A self-review pattern: finish the task first, then review it, then improve it based on the review

This also runs in a loop until no new problems are found -> so there's a chance of an infinite loop, and it's best to set a maximum number of iterations

It can be combined with the two paradigms above
