### Chapter 3 Context Engineering in Deep Agents

#### File tools

The current version of Deep Agents has seven file tools.


| Tool         | Purpose                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `ls`         | Lists the files in a directory with metadata (size, modification time)                                                  |
| `read_file`  | Reads file content with an offset and a limit (`offset` and `limit` arguments). Natively supports multimodal formats (images, video, audio, PDF/PPT) |
| `write_file` | Creates a file or fully overwrites an existing one                                                                       |
| `edit_file`  | Performs exact string replacement in an existing file                                                                    |
| `delete`     | Deletes a file or directory (**added in v0.7**)                                                                          |
| `glob`       | Finds files by pattern (for example `**/*.py`)                                                                           |
| `grep`       | Searches file content by literal match. Supports content output (`output_mode="content"`) and counts (`output_mode="count"`) |

#### Automatic context management

- Long results (20,000 tokens by default, configurable with `tool_token_limit_before_evict`) are automatically written to the virtual file system. The conversation history keeps a reference to the file path and a preview of the first 10 lines, and the agent can read the file when needed
- Conversation history summarization (compact) starts by default when 85% of the context window is used. It archives the message history, generates a summary, and passes it to the model so that the context is not lost

#### Pluggable storage backends

**StateBackend (default): temporary storage**

Stored in the LangGraph agent state
- Persists within a single conversation thread
- Disappears when the thread ends
- Files are shared between the main agent and subagents

**FilesystemBackend: local disk**

```python
from deepagents.backends import FilesystemBackend

agent = create_deep_agent(
    model=model,
    backend=FilesystemBackend(root_dir=".", virtual_mode=True)
)
```
Reads and writes the local file system directly
- `root_dir` sets the root directory the agent can access. Relative paths are resolved to absolute paths, and `.` means the current working directory (for example, when the current working directory is the root of drive D, `root_dir="."` resolves to `D:\`)
- `virtual_mode=True` enables sandboxing and prevents writes outside the root. `root_dir` alone does not restrict access as strongly
- File changes are permanent and cannot be undone

**LocalShellBackend: local shell execution**

```python
from deepagents.backends import LocalShellBackend

agent = create_deep_agent(
    model=model,
    backend=LocalShellBackend(root_dir=".", virtual_mode=True, env={"PATH": "/usr/bin:/bin"})
)
```

LocalShellBackend extends FilesystemBackend with an execute tool that runs shell commands directly on the host machine

- Commands run through `subprocess.run(shell=True)` without any sandbox isolation
- Supports arguments such as `timeout` (120 seconds by default), `max_output_bytes` (100,000 by default), and `env`
- `root_dir` is the working directory for commands, but commands can access any path on the system

Running dangerous commands is a serious risk, so take these precautions

- Point `root_dir` at a dedicated temporary workspace instead of the home directory or a directory above the repository
- Set `virtual_mode=True` explicitly and keep `env / PATH` minimal to narrow what commands can see
- Keep `.env` files, private keys, cloud credentials, and production configuration files out of directories the agent can access
- Add Human-in-the-Loop approval for high-risk operations such as `rm`, `mv`, installing dependencies, changing configuration, and network access
- When you need to run untrusted code, process user-uploaded files, or serve external users, switch to a sandbox backend instead of `LocalShellBackend`

**StoreBackend: persistence across sessions**
```python
from langgraph.store.memory import InMemoryStore
from deepagents.backends import StoreBackend

agent = create_deep_agent(
    model=model,
    backend=StoreBackend(
        namespace=lambda rt: (rt.server_info.user.identity,),  # Isolate data per user
    ),
    store=InMemoryStore()  # For development. Can be omitted when deploying to LangSmith, which provides it automatically
)
```
Files are stored in the LangGraph store

- Persists across threads, so different conversations can access the same files
- The `namespace` argument controls data isolation. `lambda rt: (rt.server_info.user.identity,)` isolates data per user so that different users' data does not mix
- Use InMemoryStore during development and omit the `store` argument when deploying to LangSmith (the platform configures it automatically)

With `rt.server_info.user.identity` in `namespace`, the value is filled in automatically when the agent is deployed to LangSmith. With a local `invoke()`, however, `rt.server_info` is `None`, and accessing it directly raises an error

```python
namespace=lambda rt: (
    (rt.server_info.user.identity,)
    if rt.server_info else
    ("local-user",)
),
```

**CompositeBackend: mixed routing**

```python
from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from langgraph.store.memory import InMemoryStore

agent = create_deep_agent(
    model=model,
    backend=CompositeBackend(
        default=StateBackend(),            # Default: temporary storage
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
                # Without LangSmith, add if rt.server_info else ("local-user",)
            ),
        }
    ),
    store=InMemoryStore()
)
```

- Agent writes `/workspace/plan.md` → StateBackend (temporary)
- Agent writes `/memories/preferences.txt` → StoreBackend (persistent, isolated per user)
- `ls`, `glob`, and `grep` automatically aggregate results from all backends and keep the path prefixes

A `/memories/` route means that a write to any folder under `/memories/` matches the StoreBackend

```python
import tempfile
from pathlib import Path

from deepagents.backends import CompositeBackend, FilesystemBackend, StateBackend

with tempfile.TemporaryDirectory() as a, tempfile.TemporaryDirectory() as b:
    memories = FilesystemBackend(root_dir=a, virtual_mode=True)
    projects = FilesystemBackend(root_dir=b, virtual_mode=True)
    backend = CompositeBackend(default=StateBackend(), routes={"/memories/": memories, "/memories/projects/": projects})

    for path in ["/memories/user/prefs.md", "/memories/2026/10/notes.md", "/memories/projects/demo/plan.md"]:
        print(path, "->", backend.write(path, "x").error or "ok")

    print("\n/memories/ maps to directory A:", sorted(p.relative_to(a).as_posix() for p in Path(a).rglob("*") if p.is_file()))
    print("/memories/projects/ maps to directory B:", sorted(p.relative_to(b).as_posix() for p in Path(b).rglob("*") if p.is_file()))
-------------------------------------------------------------------------------
```

#### Custom backends and security policies

**Declarative permissions: FilesystemPermission**

```python
from deepagents import create_deep_agent, FilesystemPermission

agent = create_deep_agent(
    model=model,
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
                # Without LangSmith, add if rt.server_info else ("local-user",)
            ),
        },
    ),
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/policies/**"],
            mode="deny",           # Deny writes to any file under /policies/
        ),
    ],
)
```
Three `mode` values:
- `allow`: allow
- `deny`: deny
- `interrupt`: wait for human approval. Requires a checkpointer and uses the same `Command(resume=...)` as tool approval

Permission rules apply the first match, so put specific rules before broader ones

**Security policy: PolicyWrapper**

For cases that need interception policies (rate limiting, audit logs, content checks)

Option 1: subclass an existing backend

```python
from deepagents.backends.filesystem import FilesystemBackend
from deepagents.backends.protocol import WriteResult, EditResult, DeleteResult

class GuardedBackend(FilesystemBackend):
    def __init__(self, *, deny_prefixes: list[str], **kwargs):
        super().__init__(**kwargs)
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in deny_prefixes]

    def write(self, file_path: str, content: str) -> WriteResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return WriteResult(error=f"Write denied: {file_path}")
        return super().write(file_path, content)

    def edit(self, file_path: str, old_string: str, new_string: str,
             replace_all: bool = False) -> EditResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return EditResult(error=f"Edit denied: {file_path}")
        return super().edit(file_path, old_string, new_string, replace_all)

    def delete(self, file_path: str) -> DeleteResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return DeleteResult(error=f"Delete denied: {file_path}")
        return super().delete(file_path)
```

Option 2: a generic wrapper (works with any backend)

```python
from deepagents.backends.protocol import BackendProtocol, WriteResult, EditResult, DeleteResult

class PolicyWrapper(BackendProtocol):
    def __init__(self, inner: BackendProtocol, deny_prefixes: list[str]):
        self.inner = inner
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in deny_prefixes]

    def _deny(self, path: str) -> bool:
        return any(path.startswith(p) for p in self.deny_prefixes)

    def ls(self, path): return self.inner.ls(path)
    def read(self, file_path, offset=0, limit=2000): return self.inner.read(file_path, offset=offset, limit=limit)
    def grep(self, pattern, path=None, glob=None): return self.inner.grep(pattern, path, glob)
    def glob(self, pattern, path="/"): return self.inner.glob(pattern, path)

    def write(self, file_path: str, content: str) -> WriteResult:
        if self._deny(file_path):
            return WriteResult(error=f"Write denied: {file_path}")
        return self.inner.write(file_path, content)

    def edit(self, file_path: str, old_string: str, new_string: str,
             replace_all: bool = False) -> EditResult:
        if self._deny(file_path):
            return EditResult(error=f"Edit denied: {file_path}")
        return self.inner.edit(file_path, old_string, new_string, replace_all)

    def delete(self, file_path: str) -> DeleteResult:
        if self._deny(file_path):
            return DeleteResult(error=f"Delete denied: {file_path}")
        return self.inner.delete(file_path)
```

#### Thoughts

The virtual file system seems to separate files meant for the AI from files meant for people, and the AI-facing files no longer take up local disk space. Because storage choices can affect the runtime environment, AI security matters, and Deep Agents offers several storage options that can be combined flexibly. It also lets you define read and write permissions, and when you need a custom security policy in the storage backend, you can subclass an existing class and override each tool.
