## Troubleshooting

### Environment setup

Background: The machine only had Windows at first, and installing Ubuntu was not part of the plan.

Problem: The database configuration kept failing.

Cause: The project's `.env` sets `SEEKDB_EMBED=true`, which uses SeekDB embedded mode. `pyseekdb` depends on the native library `pylibseekdb`, and `uv.lock` installs `pylibseekdb` only under this condition:

```text
(platform_machine == 'arm64' and sys_platform == 'darwin') or sys_platform == 'linux'
```

`pylibseekdb` 1.4.0.post1 ships packages only for macOS arm64 and Linux (x86_64, aarch64), so it is not installed on Windows.

Fix: Run the project in Ubuntu on WSL2.

1. Open PowerShell, run `wsl --install`, and restart Windows when it finishes.
2. Open Ubuntu and create a Linux user.
3. Access drive D with the following command (`cd D:\...` fails with `No such file or directory`).

   ```bash
   cd "/mnt/d/资料/资料/公司/个人/deepagent/research_deepagent"
   ```

### Backend unreachable

Background: Running `agentseek dev` in Ubuntu reported errors.

Problem:

- The frontend shows `ConnectionError: Unable to connect to LangGraph server. ... Failed to fetch`.
- In `agentseek doctor --live`, the frontend (5174) passes and the backend reports `fail langgraph: http://127.0.0.1:2024/health is not reachable.`.
- The backend log shows `Application startup complete.` and the backend responds to `/docs`, then it shuts down on its own. The last line is:

  ```text
  Timed out waiting for 'http://localhost:2024' to become ready: <urlopen error [Errno 111] Connection refused>
  ```

- Once the backend is reachable, sending a message fails with `OpenAIConnectionError: Connection error.`, and LangSmith uploads fail with `ProxyError` (connection to `127.0.0.1:7890` refused).

Cause: `127.0.0.1:7890` is unavailable, so every request sent through the proxy fails.

- After starting, `agentseek-api dev` polls `http://localhost:2024/ok` and `/health` with `urllib.request.urlopen` to check whether the backend is ready (`_wait_for_dev_server_ready` in `agentseek_api/cli.py`). `urllib` reads `HTTP_PROXY`, so when `NO_PROXY` is not set, requests to `localhost` also go to the proxy. When polling times out, the launcher stops the backend, which is why port 2024 is unreachable.
- Requests to the model API and LangSmith go through the same proxy. In a curl comparison, `https://api.openai.com/v1/models` returns `HTTP 000` through the proxy and `HTTP 401` with `--noproxy '*'` (a direct connection). The request carries no API key, so the 401 means the network connection works.

Fix: In the same terminal that runs `agentseek dev`, clear the proxy variables and exclude local addresses from the proxy.

```bash
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY http_proxy https_proxy all_proxy
export NO_PROXY="localhost,127.0.0.1,::1"
export no_proxy="$NO_PROXY"
agentseek dev
```

After this, both `langgraph` and `frontend` show `ok` in `agentseek doctor --live`. If you need a proxy, replace the address with one that works and keep `NO_PROXY`.
