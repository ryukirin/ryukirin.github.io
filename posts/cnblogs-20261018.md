## 笔记

### 第四章 任务规划与分解 — 让 Agent 学会拆解复杂任务

#### todo 的三种状态

| 状态        | 含义   | 典型场景                     |
| ----------- | ------ | ---------------------------- |
| pending     | 待办   | Agent 刚规划出来，还没开始做 |
| in_progress | 进行中 | Agent 正在执行这个步骤       |
| completed   | 已完成 | Agent 将任务标记为完成       |

agent 更新 todo 的例子：

调用 `write_todos` 
```
Updated todo list to [{'content': '搜集2026-10-17前后最新AI新闻（多来源搜索）', 'status': 'in_progress'}, {'content': '对搜索结果去重，形成候选新闻清单', 'status': 'pending'}, {'content': '与 /history/news_history.txt 比对，剔除已报道过的新闻', 'status': 'pending'}, {'content': '将新新闻的标题+摘要追加写入 history/news_history.txt', 'status': 'pending'}, {'content': '撰写报告并保存为 report/2026-10-17.md', 'status': 'pending'}]
```

#### todo 清单的持久化

任务清单保存在 Agent State 的 todos 字段中

```json
{
    "todos":[
        {
            "content":"搜集2026-10-17前后最新AI新闻（多来源搜索）",
            "status":"in_progress"
        },
        {
            "content":"对搜索结果去重，形成候选新闻清单",
            "status":"pending"
        },
        {
            "content":"与 /history/news_history.txt 比对，剔除已报道过的新闻",
            "status":"pending"
        },
        {
            "content":"将新新闻的标题+摘要追加写入 history/news_history.txt",
            "status":"pending"
        },
        {
            "content":"撰写报告并保存为 report/2026-10-17.md",
            "status":"pending"
        }
    ]
}
```

- 多次 `invoke()` 之间要自动接续清单，需要配置 Checkpointer，并复用同一个 `thread_id`；只添加 `TodoListMiddleware` 不会自动接续上次运行的状态
- `InMemorySaver` 只在当前进程中保存检查点；进程重启后还要恢复，需要使用数据库等持久化 Checkpointer。部署到 Agent Server 时，由平台提供相应的持久化能力
- `subagents=[...]` 声明的子 Agent 有独立 Middleware 栈，需要规划能力时必须在自己的 spec 中启用 Todo；它也不会读取主 Agent 的清单

#### LangChain 中间件

`create_deep_agent()` 内部做的事情，本质上就是把一组中间件自动组装到了 Agent 上

**两类 Hook**

| 风格       | Hook                                                         | 执行方式                                                     | 适合场景                         |
| ---------- | ------------------------------------------------------------ | ------------------------------------------------------------ | -------------------------------- |
| Node-style | `before_agent`、`before_model`、`after_model`、`after_agent` | 编译成 Agent 图中的独立节点，按生命周期顺序运行              | 校验、状态更新、审计、人工中断   |
| Wrap-style | `wrap_model_call`、`wrap_tool_call`                          | 包裹一次模型或工具调用；可以不调用、调用一次或多次 `handler` | 重试、缓存、降级、请求或响应转换 |

设置人工中断时，因为 Node-style 有明显的图节点边界，所以更适合设置人工中断 `interrupt()`

**默认中间件**

- `FilesystemMiddleware` ：注入 7 个文件工具，并执行 permissions 权限规则
- `SummarizationMiddleware` ：上下文自动压缩，触发阈值可配置
- `PatchToolCallsMiddleware` ：补齐消息历史中缺失的工具响应
- Prompt caching 等模型相关能力 ：是否启用取决于模型和 Harness profile

**参数配置中间件**

- `SubAgentMiddleware` ：由 `subagents=` 配置，默认包含 general-purpose 子 Agent；提供 task 工具
- `SkillsMiddleware` ：传入 `skills=` 参数时启用，注入技能包
- `AsyncSubAgentMiddleware` ：传入异步子 Agent 时启用
- `MemoryMiddleware` ：传入 `memory=` 参数时启用，注入 AGENTS.md 记忆
- `HumanInTheLoopMiddleware` ：传入 `interrupt_on=` 参数时启用，拦截指定工具调用等待人工审批

**`middleware=[...]` 配置中间件**

- `TodoListMiddleware` 等可选策略可以按需加入
- 与默认 Middleware 同名的实例会在原位置换默认实例，而不是在末尾再叠加一个
- 原位置换是完整实例替换，不会把新旧配置按字段合并


| 类别   | 中间件                   | 用途                                           |
| ------ | ------------------------ | ---------------------------------------------- |
| 规划   | TodoListMiddleware       | 任务规划与追踪，注入 write_todos 和 todos 状态 |
| 安全   | PIIMiddleware            | 个人信息检测和脱敏                             |
| 弹性   | ToolRetryMiddleware      | 工具调用失败自动重试                           |
| 弹性   | ModelRetryMiddleware     | 模型调用失败自动重试                           |
| 弹性   | ModelFallbackMiddleware  | 主模型失败自动切换备用模型                     |
| 限制   | ToolCallLimitMiddleware  | 限制工具调用次数                               |
| 限制   | ModelCallLimitMiddleware | 限制模型调用次数                               |
| 上下文 | ContextEditingMiddleware | 清理旧的工具调用结果                           |

#### PatchToolCallsMiddleware（Node-style）

在历史消息中只有工具调用请求，而没有工具响应消息的情况下（比如取消运行或者参数损坏）进行下一次运行的时候，`PatchToolCallsMiddleware` 会在 `before_agent` Hook 中检查历史消息，为缺失的响应消息补上一条 `ToolMessage`，说明这次调用被取消。对于参数损坏或截断的调用，则说明它未能执行。

```python
from langchain_core.messages import AIMessage
from langgraph.checkpoint.memory import InMemorySaver

# 课程项目 deepagents-in-action 里的测试用模型，按顺序返回 responses 中预设的回复
from course_notebooks.testing import ScriptedChatModel
from deepagents import create_deep_agent

executed = []  # 记录 echo 是否真的执行过


def echo(text: str) -> str:
    """Return the text unchanged."""
    executed.append(text)
    return f"echo: {text}"


model = ScriptedChatModel(responses=[
    AIMessage(content="", tool_calls=[{"name": "echo", "args": {"text": "hello"}, "id": "call_1"}]),
    AIMessage(content="第二次运行的回复"),
])
agent = create_deep_agent(model=model, tools=[echo], checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "demo"}}


def show(title):
    """
    打印检查点里保存的消息
    args:
        title: 本次打印的标题
    return:
        None
    """
    print(f"\n== {title}")
    for m in agent.get_state(config).values["messages"]:
        calls = [c["id"] for c in getattr(m, "tool_calls", [])]
        extra = f" tool_calls={calls}" if calls else ""
        extra += f" tool_call_id={m.tool_call_id} status={m.status}" if m.type == "tool" else ""
        print(f"  {m.type:<6}{extra}  {str(m.content)[:60]!r}")


# 第一次运行：model 节点一结束就停止，模拟用户取消、进程崩溃、超时等情况
for update in agent.stream({"messages": [{"role": "user", "content": "echo hello"}]}, config, stream_mode="updates"):
    print("完成的节点:", list(update))
    if "model" in update:
        break

show("第一次运行被取消后，检查点里的消息")
print("  echo 执行次数:", len(executed))

# 第二次运行：同一个 thread_id，before_agent 先检查历史，补齐缺失的工具响应
agent.invoke({"messages": [{"role": "user", "content": "继续"}]}, config)
show("第二次运行之后，检查点里的消息")
print("  echo 执行次数:", len(executed))
------------------------------------------
完成的节点: ['PatchToolCallsMiddleware.before_agent']
完成的节点: ['model']

== 第一次运行被取消后，检查点里的消息
  human   'echo hello'
  ai     tool_calls=['call_1']  ''
  echo 执行次数: 0

== 第二次运行之后，检查点里的消息
  human   'echo hello'
  ai     tool_calls=['call_1']  ''
  tool   tool_call_id=call_1 status=error  'Tool call echo with id call_1 did not complete - no result w'
  human   '继续'
  ai      '第二次运行的回复'
  echo 执行次数: 0
```

`tool   tool_call_id=call_1 status=error  'Tool call echo with id call_1 did not complete - no result w'` 就是补齐的 `ToolMessage`

对于运行中不同的异常情况，处理方式如下：


| 遇到什么情况                     | 谁来处理                                | 需要注意什么                                         |
| -------------------------------- | --------------------------------------- | ---------------------------------------------------- |
| 历史里有工具调用，却缺少对应响应 | `PatchToolCallsMiddleware` 补充说明消息 | 不重试工具，不验证结果是否正确                       |
| 工具调用遇到可重试的异常         | 应用显式配置的 `ToolRetryMiddleware`    | 是否重试、重试次数由策略决定；写操作还要考虑重复执行 |
| 下一次运行继续上一次的状态       | Checkpointer 配合同一个 `thread_id`     | 跨进程恢复需要持久化 Checkpointer                    |
| 工具返回了内容，但内容是否正确   | 应用的校验、评测或人工审核              | 调用成功、清单完成都不等于结果正确                   |

#### TodoListMiddleware（两个方式都用了）

- `wrap_model_call` ：每次调用模型的时候，把规划提示词加进这一次的请求
- `after_model` ：模型回复之后检查同一条回复里有没有并行调用好几次 `write_todos`，有的话就返回错误


`write_todos` 的底层实现是 LangChain 的 `TodoListMiddleware` 添加后，Agent 会自动获得：

- `write_todos` 工具：创建和管理任务清单
- `todos` 状态：保存任务及其状态，供后续步骤和 UI 使用；跨次调用的接续由 Checkpointer 负责
- 规划指导提示词：引导 Agent 在面对复杂任务时先规划再执行

**自定义配置**

`TodoListMiddleware` 可以设置以下两个参数
```python
TodoListMiddleware(
    system_prompt="...",      # 自定义规划指导提示词
    tool_description="...",   # 自定义 write_todos 工具的描述
)
```

#### SummarizationMiddleware（Wrap-style）

负责上下文压缩。

需要按路径读回历史时，还要配置使用同一 Backend 的 `FilesystemMiddleware`。提供 `compact_conversation` 工具（手动压缩）的则是另一个 `SummarizationToolMiddleware`，与这里的自动摘要分开配置。

自动提供摘要的阈值，想要自己覆盖也可以。

```python
from deepagents import create_deep_agent
from deepagents.backends import StateBackend
from deepagents.middleware.summarization import SummarizationMiddleware

# 换成 FilesystemBackend 等自己保存数据的 backend 时，要把这一个对象传给所有用到它的地方
backend = StateBackend()

agent = create_deep_agent(
    model=model,
    # FilesystemMiddleware 不用自己配，create_deep_agent 会用这个 backend 自动装上
    backend=backend,
    middleware=[
        # 与默认摘要中间件同名，原地替换。必须设置 trigger，否则不会自动摘要
        SummarizationMiddleware(
            model=model, 
            backend=backend, 
            trigger=("tokens", 100000), 
            keep=("messages", 6)
        ),
    ],
)
```

**和 LangChain 的版本对比**

在 LangChain 中属于 Node-style，执行位置在`before_model` / `abefore_model`，将当前 `state["messages"]` 中的旧消息替换为摘要，保留近期消息。
在 Deep Agents 中属于 Wrap-style，在模型调用时执行，保留原始消息，另外记录摘要和截断位置，并将待总结的旧消息写入 Backend，摘要中附上保存路径。
