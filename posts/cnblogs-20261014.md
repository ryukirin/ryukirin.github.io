### 第三章 Deep Agents 的 Context Engineering

#### 文件工具

Deep Agents 当前版本有七个文件工具


| 工具         | 用途                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| `ls`         | 列出目录中的文件和元信息（大小、修改时间）                                                                 |
| `read_file`  | 读取文件内容，支持偏移量和限制条数（`offset`和`limit`参数）原生支持多模态格式（图片、视频、音频、PDF/PPT） |
| `write_file` | 创建文件，或完整覆盖已有文件                                                                               |
| `edit_file`  | 对已有文件做精确字符串替换                                                                                 |
| `delete`     | 删除文件或目录（**v0.7版本新增**）                                                                         |
| `glob`       | 按模式匹配查找文件（如 `**/*.py`）                                                                         |
| `grep`       | 搜索文件内容，按字面量匹配；支持内容输出（`output_mode="content"`）和计数（`output_mode="count"`）         |

#### 上下文自动管理

- 长文结果（默认20,000 tokens，可通过`tool_token_limit_before_evict`设置）自动写入虚拟文件系统，在对话历史中文件路径引用并显示前10行预览，Agent 可以按需读取
- 历史对话总结（compact）默认上下文窗口消耗85%的时候启用，将消息历史留档，生成摘要交给模型，防止上下文丢失

#### 可插拔的存储后端

**StateBackend（默认）：临时存储**

存在 LangGraph 的 Agent State 中
- 一个对话线程中持久化
- 对话线程结束后消失
- 主 Agent 和子 Agent 共享文件

**FilesystemBackend：本地磁盘**

```python
from deepagents.backends import FilesystemBackend

agent = create_deep_agent(
    model=model,
    backend=FilesystemBackend(root_dir=".", virtual_mode=True)
)
```
直接读写本地文件系统
- `root_dir` 指定可访问的根目录，相对路径会被解析为绝对路径，`.` 表示当前工作目录（例：当前工作目录为 D 盘根目录时，`root_dir="."` 会被解析成 `D:\`）
- `virtual_mode=True` 启用沙箱，防止越界改写，`root_dir` 约束力没有这个强
- 文件修改是永久且不可逆的

**LocalShellBackend：本地 Shell 执行**

```python
from deepagents.backends import LocalShellBackend

agent = create_deep_agent(
    model=model,
    backend=LocalShellBackend(root_dir=".", virtual_mode=True, env={"PATH": "/usr/bin:/bin"})
)
```

LocalShellBackend 是 FilesystemBackend 的扩展，额外提供 execute 工具，可直接在宿主机运行 Shell 命令

- 命令通过 `subprocess.run(shell=True)` 执行，无任何沙箱隔离
- 支持 `timeout`（默认 120 秒）、`max_output_bytes`（默认 100,000）、`env` 等参数
- `root_dir` 作为命令的工作目录，但命令可访问系统上任意路径

因为执行危险指令的风险很大，所以防护很重要

- 将 `root_dir` 指向一个专门的临时工作区，而不是用户主目录或整个仓库上级目录
- 显式设置 `virtual_mode=True`，并用最小化的 `env / PATH` 降低命令可见范围
- 不把 `.env`、私钥、云凭证、生产配置文件放进 Agent 可访问目录
- 对 `rm`、`mv`、安装依赖、修改配置、访问网络等高风险操作增加 Human-in-the-Loop 审批
- 需要运行不可信代码、处理用户上传文件或对外提供服务时，直接换用沙箱后端，不要用 `LocalShellBackend`

**StoreBackend：跨会话持久化**
```python
from langgraph.store.memory import InMemoryStore
from deepagents.backends import StoreBackend

agent = create_deep_agent(
    model=model,
    backend=StoreBackend(
        namespace=lambda rt: (rt.server_info.user.identity,),  # 按用户隔离数据
    ),
    store=InMemoryStore()  # 开发用；部署到 LangSmith 时可省略，平台自动提供
)
```
文件存在 LangGraph 的 Store 中

- 跨线程持久化——不同对话都能访问同一份文件
- `namespace` 参数控制数据隔离：`lambda rt: (rt.server_info.user.identity,)` 按用户隔离，防止数据混用
- 开发用 InMemoryStore，部署到 LangSmith 时省略 `store` 参数（平台自动配置）

`namespace` 用 `rt.server_info.user.identity` 部署到 LangSmith 时能自动赋予，但本地 `invoke()` 时 `rt.server_info` 是 `None`，直接访问会报错

```python
namespace=lambda rt: (
    (rt.server_info.user.identity,)
    if rt.server_info else
    ("local-user",)
),
```

**CompositeBackend：混合路由**

```python
from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from langgraph.store.memory import InMemoryStore

agent = create_deep_agent(
    model=model,
    backend=CompositeBackend(
        default=StateBackend(),            # 默认：临时存储
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
                # 不接 LangSmith 的话加上 if rt.server_info else ("local-user",)
            ),
        }
    ),
    store=InMemoryStore()
)
```

- Agent 写入 `/workspace/plan.md` → StateBackend（临时）
- Agent 写入 `/memories/preferences.txt` → StoreBackend（持久化，按用户隔离）
- `ls`、`glob`、`grep` 自动聚合所有后端的结果，路径前缀保留

`/memories/` 表示写入该文件夹下任意文件夹时匹配到 StoreBackend 方式

#### 自定义后端与安全策略

**声明式权限：FilesystemPermission**

```python
from deepagents import create_deep_agent, FilesystemPermission

agent = create_deep_agent(
    model=model,
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
                # 不接 LangSmith 的话加上 if rt.server_info else ("local-user",)
            ),
        },
    ),
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/policies/**"],
            mode="deny",           # 禁止写入 /policies/ 下的任何文件
        ),
    ],
)
```
三种 `mode` ：
- `allow` 允许
- `deny` 拒绝
- `interrupt` 等待人工审批，需要Checkpointer，并使用与工具审批相同的 `Command(resume=...)`

权限规则匹配时按第一个匹配到的为准，所以具体规则要写在宽泛规则前

**安全策略：PolicyWrapper**

需要拦截策略（速率限制、审计日志、内容检查）的场景

方法1：继承现有后端

```python
from deepagents.backends.filesystem import FilesystemBackend
from deepagents.backends.protocol import WriteResult, EditResult, DeleteResult

class GuardedBackend(FilesystemBackend):
    def __init__(self, *, deny_prefixes: list[str], **kwargs):
        super().__init__(**kwargs)
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in deny_prefixes]

    def write(self, file_path: str, content: str) -> WriteResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return WriteResult(error=f"写入被拒绝：{file_path}")
        return super().write(file_path, content)

    def edit(self, file_path: str, old_string: str, new_string: str,
             replace_all: bool = False) -> EditResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return EditResult(error=f"编辑被拒绝：{file_path}")
        return super().edit(file_path, old_string, new_string, replace_all)

    def delete(self, file_path: str) -> DeleteResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return DeleteResult(error=f"删除被拒绝：{file_path}")
        return super().delete(file_path)
```

方法2：通用包装器（适用于任何后端）

```python
from deepagents.backends.protocol import BackendProtocol, WriteResult, EditResult, DeleteResult

class PolicyWrapper(BackendProtocol):
    def __init__(self, inner: BackendProtocol, deny_prefixes: list[str]):
        self.inner = inner
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in deny_prefixes]

    def _deny(self, path: str) -> bool:
        return any(path.startswith(p) for p in self.deny_prefixes)

    def ls(self, path): return self.inner.ls(path)
    def read(self, file_path, offset=0, limit=2000): return self.inner.read(file_path, offset=offset, limit=limit)
    def grep(self, pattern, path=None, glob=None): return self.inner.grep(pattern, path, glob)
    def glob(self, pattern, path="/"): return self.inner.glob(pattern, path)

    def write(self, file_path: str, content: str) -> WriteResult:
        if self._deny(file_path):
            return WriteResult(error=f"写入被拒绝：{file_path}")
        return self.inner.write(file_path, content)

    def edit(self, file_path: str, old_string: str, new_string: str,
             replace_all: bool = False) -> EditResult:
        if self._deny(file_path):
            return EditResult(error=f"编辑被拒绝：{file_path}")
        return self.inner.edit(file_path, old_string, new_string, replace_all)

    def delete(self, file_path: str) -> DeleteResult:
        if self._deny(file_path):
            return DeleteResult(error=f"删除被拒绝：{file_path}")
        return self.inner.delete(file_path)
```

#### 感想

虚拟文件系统感觉是把面向 AI 的文件和面向人类的文件做了区分，面向 AI 的不再占用本地磁盘空间。同时，因为在存储的时候会影响到运行环境，所以 AI Security 就比较重要，Deep Agents 提供了多个存储方案以及灵活组合的选择。另外还提供了读写权限的定义，如果要在存储后端定制安全策略的情况下，也可以通过继承现有类的方式重写各个工具

## 实践：AI 新闻助理接入存储后端

Task1 做的 [AI 新闻助理](https://github.com/ryukirin/ai-news-deep-agent) 每次运行都从零开始搜，结果只打印在终端里，第二天再跑分不出哪些新闻已经看过。学完第三章后，用存储后端加了两个功能：

- 保存历史新闻，下次运行时先和历史比对，只追加没出现过的新闻
- 汇总报告按日期写成 Markdown 文件，存进项目的 `report/` 目录

项目地址：[ryukirin/ai-news-deep-agent](https://github.com/ryukirin/ai-news-deep-agent)

### 路径和后端的分配

问题改成了四步，放在 `config.py` 里：

```python
USER_PROMPT = """
1. 先搜一下最近的AI新闻
2. 看看这些搜索结果中有没有重复的
3. 检查这些新闻和之前的新闻有没有重复的，过往新闻在/history/news_history.txt中
    3.1 如果没有重复的就把新闻摘要和标题追加到/history/news_history.txt中
    3.2 如果有重复的就跳过该新闻
4. 最后帮我总结一下，写成一份报告{当天日期}.md，存入report/文件夹中
"""
```

Agent 只看得到文件路径，文件实际存在哪里由 `CompositeBackend` 的路由决定。历史记录、报告和运行中的临时文件用途不同，分给了三个后端：

| Agent 中的路径              | 后端                           | 实际存储位置                                       |
| --------------------------- | ------------------------------ | -------------------------------------------------- |
| `/history/news_history.txt` | `StoreBackend` + `SqliteStore` | `news.db` 的 `store` 表，namespace 为 `local-user` |
| `/report/<日期>.md`         | `FilesystemBackend`            | 项目里的 `report/` 目录                            |
| 其他路径                    | `StateBackend`（默认）         | Agent 的 state，运行结束后不保留                   |

搜索历史是面向 AI 的文件，所以放进 StoreBackend
报告面向人类的文件，所以用了 FilesystemBackend

### Agent

```python
from langchain_openai import ChatOpenAI
from deepagents import create_deep_agent
from langchain.agents.middleware import TodoListMiddleware
from langgraph.store.sqlite import SqliteStore
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend, FilesystemBackend

from tool import internet_search, get_current_time
import config

model = ChatOpenAI(
    model=config.MODEL_NAME,
    api_key=config.DEEPSEEK_API_KEY,
    base_url=config.BASE_URL,
)

# SqliteStore 需要 pip install langgraph-checkpoint-sqlite
with SqliteStore.from_conn_string("news.db") as store:
    store.setup()  # 首次运行时建表，之后再调用不会重复建
    agent = create_deep_agent(
        model=model,
        tools=[internet_search, get_current_time],
        system_prompt=config.SYSTEM_PROMPT,
        middleware=[TodoListMiddleware()],
        backend=CompositeBackend(
            default=StateBackend(),            # 默认：临时存储
            routes={
                "/history/": StoreBackend(
                    namespace=lambda rt: (
                        (rt.server_info.user.identity,)
                        if rt.server_info else
                        ("local-user",)
                    ),
                ),
                # 路由前缀会被去掉，/report/2026-10-17.md 写到 report/2026-10-17.md
                "/report/": FilesystemBackend(root_dir="report", virtual_mode=True)
            }
        ),
        store=store,
    )

    # 读写 store 要在 with 块内，invoke 也放在里面
    result = agent.invoke(
        {"messages": [{"role": "user", "content": config.USER_PROMPT}]},
    )
```

### 试错记录

#### 报告路径

`/report/` 一开始设置的是 `FilesystemBackend(root_dir=".", virtual_mode=True)`。跑完之后没有生成 `report/` 目录，报告出现在项目根目录，文件名是 `2026-10-17.md`

原因： `CompositeBackend` 把路径交给子后端之前会先去掉路由前缀。Agent 写 `/report/2026-10-17.md`，`FilesystemBackend` 收到的是 `/2026-10-17.md`，再拼到 `root_dir` 下面

解决：把 `root_dir` 改成 `"report"` 后，报告写进了 `report/2026-10-17.md`

#### 历史记录不保存

同一次运行里，终端打印的 todo 显示“把新新闻的标题+摘要写入 /history/news_history.txt”是 completed，却找不到这个文件。

原因：当时 `/history/` 用的是 `InMemoryStore`，数据只在进程内存里，`agent.py` 一结束就没了。

`StoreBackend` 的 store 实现方式：

| store                | 数据存在哪里                             | 需要安装的包                    |
| -------------------- | ---------------------------------------- | ------------------------------- |
| `InMemoryStore`      | 进程内存，进程结束就没了                 | langgraph 自带                  |
| `SqliteStore`        | 本地的一个 `.db` 文件                    | `langgraph-checkpoint-sqlite`   |
| `PostgresStore`      | PostgreSQL 数据库，本机或云上都可以      | `langgraph-checkpoint-postgres` |
| LangSmith Deployment | 平台提供的持久化 store，不需要传 `store` | 无                              |

本项目只在本地跑，选了改动最小的 `SqliteStore`。换完之后用两个独立进程验证过，第一个进程写入 `/history/news_history.txt` 后退出，第二个进程能读到同样的内容。

#### Agent 怎么从 /history/ 读到数据库里的内容

模型看不到数据库，只能用 `ls`、`read_file`、`grep` 这些文件工具。以 `read_file("/history/news_history.txt")` 为例：

1. `CompositeBackend` 按最长前缀匹配到 `/history/`，去掉前缀，把 `/news_history.txt` 交给 `StoreBackend`
2. `StoreBackend` 用 namespace 的 lambda 算出 `("local-user",)`，调用 `store.get(("local-user",), "/news_history.txt")`
3. `SqliteStore` 按 prefix 和 key 取出 `store` 表里对应的一行
4. 取出的正文按 `offset`、`limit` 截取，加上行号后作为工具结果返回给模型

`edit_file` 追加内容时也是先 `store.get` 读出整个文件，替换后再 `store.put` 写回同一行。`grep` 会先取出这个 namespace 下的全部文件，再在 Python 里逐行做字面匹配。

读和写走的是同一套路由。`read_file`、`write_file`、`edit_file`、`delete` 按前缀选一个后端。笔记里写的“`ls`、`glob`、`grep` 自动聚合所有后端的结果”，只发生在路径是 `/` 或不传路径的时候，路径落在某个路由下时只查那一个后端。子后端返回的路径会重新加上前缀，模型看到的始终是 `/history/news_history.txt`。
