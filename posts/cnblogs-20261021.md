### 第七章 Skills — 可复用的 Agent 能力包

#### Skills 的目录结构

```
skills/
└── langgraph-docs/
    ├── SKILL.md              # Required: metadata + instructions
    ├── scripts/              # Optional: executable scripts
    │   └── fetch_docs.py
    ├── references/           # Optional: detailed docs
    │   ├── api-patterns.md
    │   └── style-guide.md
    └── assets/               # Optional: templates, data files
        ├── report-template.md
        └── schema.json
```

| 目录          | 用途                                 | 加载时机                                      |
| ------------- | ------------------------------------ | --------------------------------------------- |
| `SKILL.md`    | 元数据 + 核心指令                    | 元数据启动时进入提示词；正文由 Agent 按需读取 |
| `scripts/`    | 可执行脚本（Python、Bash、JS 等）    | Agent 按指令需要时执行                        |
| `references/` | 详细参考文档（API 模式、风格指南等） | Agent 需要深入信息时按需读取                  |
| `assets/`     | 模板、数据文件、schema 等静态资源    | Agent 需要时按需读取                          |

#### `SKILL.md` 的结构

分为 YAML frontmatter 和 Markdown body （指令正文）

**YAML frontmatter**


| 字段          | 必填 | 说明                                                           |
| ------------- | ---- | -------------------------------------------------------------- |
| name          | Yes  | 小写字母、数字、连字符组成，1-64 字符。必须与父目录名一致。    |
| description   | Yes  | 描述 Skill 的功能和适用场景。最大 1024 字符。                  |
| license       | No   | 许可证名称                                                     |
| compatibility | No   | 环境要求（如需要网络访问、需要特定 CLI 工具）。最大 500 字符。 |
| metadata      | No   | 任意键值对（author、version、entrypoint 等）                   |
| allowed-tools | No   | 空格分隔的预授权工具列表                                       |

**description 是最重要的字段**

- 好的 description：有具体、明确触发条件
- 差的 description：模糊、缺乏触发信号

差的 description 会导致两种问题：该用时匹配不到（漏召回），不该用时被错误触发（误召回）

#### Progressive Disclosure：渐进式加载

Skills 并非一下子把全部的内容都交给模型，这样会导致上下文被太多的噪音填满。所以渐进式加载把 Skills 分成三层，在必要的时候逐渐交给模型。

| 层级                  | 加载内容                                      | 加载时机                                 | 处理者                         |
| --------------------- | --------------------------------------------- | ---------------------------------------- | ------------------------------ |
| Level 1: Metadata     | `name` + `description` + 文件路径             | Agent 启动时，加载可发现的 Skills 元数据 | `SkillsMiddleware`             |
| Level 2: Instructions | `SKILL.md` 正文                               | Agent 判断相关后调用 `read_file`         | LLM 决策，通过文件系统工具读取 |
| Level 3: Resources    | `scripts/`、`references/`、`assets/` 下的文件 | 指令中引用到某个文件时                   | LLM 自行决策读取               |

工作流程：

- **启动阶段**：`SkillsMiddleware` 扫描配置目录下的 Skill 子目录，从各个 `SKILL.md` 的 frontmatter 提取 `name` 和 `description` 放进系统提示词

- **读取阶段**：`SkillsMiddleware` 提供可用 Skills 列表和读取指引，在用户发送请求后，Agent 根据 `description` 判断是否需要某个 Skill，再用 `read_file` 读取对应的 `SKILL.md` 把正文放入上下文。

- **执行阶段**：Agent 按照正文中的指令工作。如果指令中引用了 `references/` 或 `assets/` 下的文件，Agent 自行决定是否读取。这一步由 LLM 控制，不再由中间件干预。

#### 多源 Skills 与优先级

Skills 可以通过 `create_deep_agent` 的 `skills` 参数传入路径

```python
agent = create_deep_agent(
    model=model,
    backend=backend,
    skills=[path1,...],
)
```

当多个路径中存在同名 Skill 时，后面的覆盖前面的

假设项目规则优先于团队规则的情况

```
skills/
├── team/                           ← 团队共享版本（优先级低）
│   ├── report-format/SKILL.md      ← 团队版报告格式
│   └── citation-style/SKILL.md     ← 团队版引用格式
└── project/                        ← 本项目版本（优先级高）
    └── report-format/SKILL.md      ← 项目版报告格式
```

那么传入的时候可以

```python
agent = create_deep_agent(
    model=model,
    backend=backend,
    skills=["/skills/team/", "/skills/project/"],
)
```
这样一来在写报告的时候自动使用项目报告格式，但是引用的时候还是遵循团队的格式

运行结果

```
== skills=['/skills/team/', '/skills/project/']
   **Team Skills**: `/skills/team/`
   **Project Skills**: `/skills/project/` (higher priority)
   - **citation-style**: 报告中需要引用来源时使用。提供团队统一的引用编号格式。
   -> Read `/skills/team/citation-style/SKILL.md` for full instructions
   - **report-format**: 撰写 AI 新闻日报时使用。提供本项目的报告结构（……）。
   -> Read `/skills/project/report-format/SKILL.md` for full instructions
```

典型的分层策略：

| 层级   | 路径               | 内容                         |
| ------ | ------------------ | ---------------------------- |
| 组织级 | `/skills/org/`     | 公司规范、安全审查           |
| 团队级 | `/skills/team/`    | 团队工作流、Code Review 标准 |
| 项目级 | `/skills/project/` | 项目特定的部署流程、测试策略 |



#### 使用方式

Deep Agents 提供三种 Backend 来加载 Skills，各自对应不同的文件存储策略。

**基本用法（FilesystemBackend）**

直接从本地磁盘读取 Skills 文件，适合本地开发和 CLI 场景

```python
from deepagents import create_deep_agent
from deepagents.backends.filesystem import FilesystemBackend

backend = FilesystemBackend(root_dir="./my-project", virtual_mode=True)

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=backend,
    # Skill 子目录的父目录 可以多个
    # 路径使用正斜杠/
    skills=["/skills/"],
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "What is LangGraph?"}]},
    config={"configurable": {"thread_id": "1"}},
)
```

**StateBackend：通过 state 注入 Skills**

StateBackend 将文件存储在 LangGraph 的 agent state 中。适合无磁盘环境（如 serverless 部署）或需要动态注入 Skill 内容的场景
虚拟路径必须以 / 开头（绝对路径格式）


```python
from urllib.request import urlopen
from deepagents import create_deep_agent
from deepagents.backends import StateBackend
from deepagents.backends.utils import create_file_data
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()
backend = StateBackend()

# 从远程加载 Skill（也可以本地读取）
skill_url = "https://raw.githubusercontent.com/langchain-ai/deepagents/refs/heads/main/libs/code/examples/skills/langgraph-docs/SKILL.md"
with urlopen(skill_url) as response:
    skill_content = response.read().decode('utf-8')

# 必须使用 create_file_data() 格式化内容
skills_files = {
    "/skills/langgraph-docs/SKILL.md": create_file_data(skill_content),
}

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=backend,
    skills=["/skills/"],
    checkpointer=checkpointer,
)

result = agent.invoke(
    {
        "messages": [{"role": "user", "content": "What is langgraph?"}],
        # 通过 files 参数注入 每次调用都需要传入
        "files": skills_files,  
    },
    config={"configurable": {"thread_id": "12345"}},
)
```

**StoreBackend：跨线程持久化**

StoreBackend 使用 LangGraph Store 进行持久化存储。文件只需写入一次，所有线程都能访问。也就是说 Skill 只写一次，所有会话都能读到。

```python
from urllib.request import urlopen
from deepagents import create_deep_agent
from deepagents.backends import StoreBackend
from deepagents.backends.utils import create_file_data
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()
# namespace 参数是一个函数 接收 runtime config 并返回命名空间元组
backend = StoreBackend(namespace=lambda _rt: ("filesystem",))

skill_url = "https://raw.githubusercontent.com/langchain-ai/deepagents/refs/heads/main/libs/code/examples/skills/langgraph-docs/SKILL.md"
with urlopen(skill_url) as response:
    skill_content = response.read().decode('utf-8')

# 在这里注入文件 不用每次 invoke 都传入
store.put(
    namespace=("filesystem",),
    key="/skills/langgraph-docs/SKILL.md",
    value=create_file_data(skill_content),
)

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=backend,
    store=store,
    skills=["/skills/"],
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "What is langgraph?"}]},
    config={"configurable": {"thread_id": "12345"}},
)
```

关于 `namespace` ：
- `namespace` 是 Store 里的"抽屉"，它决定一份数据和谁共享、和谁隔离
- `namespace` 用的是元组，因为它是分层的
- Store 里的每一条数据都有一个两段式的地址 `(namespace, key)` 表示哪个抽屉里的哪份文件（文件路径去掉路由前缀 `/memories/` ）
- 这里 `namespace` 写成函数是因为可以通过参数来分到不同的 `namespace`
  ```python
  # 不同的 user_id 导向不同的 namespace
  # rt 是 runtime 的缩写
  # rt.context.user_id 可以从
  # agent = create_deep_agent(...,context_schema=TenantContext) 声明结构
  # 在每次 invoke(..., context=UserContext(user_id=...)) 传进来
  # UserContext 是自己定义的 dataclass 类
  lambda rt: ("users", rt.context.user_id)
  ```
  这样写等价于
  ```python
  def pick_namespace(rt):
    return ("users", rt.context.user_id)
  ```
- 详细内容第八章会讲到

**运行时动态加载**

可以根据用户角色，租户或者请求类型加载不同的 Skill 集合
- 基于用户角色：工程师看到代码相关 Skills，数据团队看到分析 Skills
- 基于租户配置：SaaS 场景中不同客户启用不同的 Skill 包
- 基于请求上下文：根据用户输入的意图预先筛选相关 Skills
- 基于环境变量：开发环境加载调试 Skills，生产环境加载运维 Skills

```python
from deepagents import create_deep_agent

SKILLS_BY_ROLE = {
    "engineering": ["/skills/code-review/", "/skills/testing/", "/skills/deployment/"],
    "data": ["/skills/sql-analysis/", "/skills/visualization/", "/skills/data-pipeline/"],
    "support": ["/skills/ticket-triage/", "/skills/runbook/"],
}

def create_agent_for_user(user_role: str):
    return create_deep_agent(
        model="anthropic:claude-sonnet-4-6",
        skills=SKILLS_BY_ROLE.get(user_role, []),
    )
```

#### Skill 权限控制

生产环境中，Skill 的权限管理需要关注三个维度：

- 可见性（Visibility）：Agent 能否发现和读取某个 Skill
- 写入权限（Write Access）：Agent 能否修改 Skill 文件内容
- 审批流程（Approval）：写入操作是否需要人类确认

**只读 Skills（企业知识库场景）**

使用 `FilesystemPermission` 配合 `CompositeBackend` 实现，禁止对 `skills` 文件夹的 `write` 权限 

```python
from dataclasses import dataclass

from deepagents import FilesystemPermission, create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from deepagents.backends.utils import create_file_data
from langgraph.store.memory import InMemoryStore

# 保存每个租客的组织编号
@dataclass(frozen=True)
class TenantContext:
    org_id: str

def org_skill_namespace(rt):
    # 读取 rt.context.org_id
    # 如果没有 org_id 就返回 "default-org"
    org_id = getattr(rt.context, "org_id", "default-org")
    return ("curated-skills", org_id)

store = InMemoryStore()
store.put(
    # 这个 skill 是 "org-acme" 专用的
    namespace=("curated-skills", "org-acme"),
    # /skills/ 是 CompositeBackend 的挂载前缀 Store 内使用路由相对路径。
    key="/test-skill/SKILL.md",
    value=create_file_data("""---
name: test-skill
description: 用于验证只读 Skill 的发现与加载。
---

# test-skill
"""),
)

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    # 定义 context 的结构
    context_schema=TenantContext,
    backend=CompositeBackend(
        default=StateBackend(),
        # 当要对 "/skills/" 进行操作时适配命名空间
        routes={
            "/skills/": StoreBackend(
                namespace=org_skill_namespace,
            ),
        },
    ),
    skills=["/skills/"],
    permissions=[
        FilesystemPermission(
            # write_file edit_file 和 delete 都会被拒绝
            operations=["write"],
            paths=["/skills/**"],
            mode="deny",
        ),
    ],
    store=store,
)

agent.invoke(
    {"messages": [{"role": "user", "content": "列出可用 Skills"}]},
    # 在调用时传入 context
    context=TenantContext(org_id="org-acme"),
    config={"configurable": {"thread_id": "1"}},
)
```

**写入需审批（interrupt 模式）**

允许 Agent 提出修改建议，但需要人类审批后才能生效

```python
from deepagents import FilesystemPermission, create_deep_agent
from langgraph.checkpoint.memory import MemorySaver

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    skills=["/skills/personal/"],
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/skills/**"],
            mode="interrupt",
        ),
    ],
    checkpointer=MemorySaver(),  # interrupt 需要 checkpointer
)
```
- `interrupt` 模式依赖 checkpointer 保存暂停时的状态，因此必须配置 `MemorySaver` 或其他持久化 checkpointer
- 此功能需要 `deepagents>=0.6.8`
- 在 LangGraph Studio 中，`interrupt` 会自动渲染为审批 UI；API 调用时需要客户端轮询状态并提交审批结果

**共享 + 个人 Skills 分层**

实际部署中，最常见的模式是两层结构：团队共享的只读 Skill 库 + 用户个人的可写 Skill 空间

```python
from dataclasses import dataclass
from langchain_openai import ChatOpenAI
from deepagents import FilesystemPermission, create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from deepagents.backends.utils import create_file_data
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore
# 我自己写的文件，用来传入 .env 的 key 和各种配置
import config

@dataclass(frozen=True)
class TenantContext:
    org_id: str
    user_id: str

def shared_skill_namespace(rt):
    org_id = getattr(rt.context, "org_id", "default-org")
    return ("curated-skills", org_id)

def personal_skill_namespace(rt):
    if rt.server_info and rt.server_info.user:
        return ("user-skills", rt.server_info.user.identity)
    user_id = getattr(rt.context, "user_id", "local-user")
    return ("user-skills", user_id)

store = InMemoryStore()

# 装载共享 skills 和个人 skills
store.put(
    # org-acme 专用
    namespace=("curated-skills", "org-acme"),
    key="/team-report/SKILL.md",
    value=create_file_data("---\nname: team-report\ndescription: 团队共享的日报格式\n---\n\n# team-report\n")
)
store.put(
    # alice 专用
    namespace=("user-skills", "alice"),
    key="/my-notes/SKILL.md",
    value=create_file_data("---\nname: my-notes\ndescription: alice 个人的笔记格式\n---\n\n# my-notes\n")
)

model = ChatOpenAI(
    model=config.MODEL_NAME, 
    api_key=config.DEEPSEEK_API_KEY, 
    base_url=config.BASE_URL,
)

agent = create_deep_agent(
    model=model,
    context_schema=TenantContext,
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/skills/shared/": StoreBackend(
                namespace=shared_skill_namespace,
            ),
            "/skills/personal/": StoreBackend(
                namespace=personal_skill_namespace,
            ),
        },
    ),
    skills=["/skills/shared/", "/skills/personal/"],
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/skills/shared/**"],
            mode="deny",
        ),
    ],
    store=store,
    checkpointer=InMemorySaver(),
)

# 线程编号 get_state 按它找到这次运行保存的状态
config = {"configurable": {"thread_id": "t1"}}
result = agent.invoke(
    {"messages": [{"role": "user", "content": "列出可用 Skills"}]},
    context=TenantContext(org_id="org-acme", user_id="alice"),
    config=config
)
print(result["messages"][-1].content)

# 读取线程 t1 的完整状态 包括 invoke 返回值里没有的 skills_metadata
values = agent.get_state(config).values
for s in values.get("skills_metadata") or []:
    print(s["name"], "|", s["path"], "|", s["description"])
print("加载错误:", values.get("skills_load_errors"))
```

#### 用 Skills 执行代码

**沙箱脚本（Sandbox Scripts）**

如果 Skill 文件存储在沙箱之外（比如使用 StateBackend），需要通过自定义中间件在 Agent 运行前后同步文件：

- `before_agent`：将 Skill 脚本上传到沙箱环境
- `after_agent`：将沙箱中的输出文件下载回来

这种模式适合需要运行数据处理、API 调用、文件转换等任务的场景，同时保证了执行的安全隔离

**解释器技能（Interpreter Skills）**

解释器技能将 Skill 中的代码模块暴露给 Agent 的代码解释器环境
Agent 可以直接 import 经过测试的辅助函数，而不必每次都重新生成逻辑
但是需要提前安装 QuickJS 中间件

要让一个 Skill 可被导入，需要三步配置：

- 在 frontmatter 的 `metadata.entrypoint` 中指定入口文件（JS/TS）
- 配置 `CodeInterpreterMiddleware` 使用相同的后端
- Agent 在代码中通过 `await import("@/skills/<name>")` 导入

[示例代码](https://datawhalechina.github.io/deepagents-in-action/chapters/ch07-skills/#%E8%A7%A3%E9%87%8A%E5%99%A8%E6%8A%80%E8%83%BDinterpreter-skills)

#### Skills、Memory 与 Tools 对比


|          | Skills                           | Memory（`AGENTS.md`）    | Tools                                |
| -------- | -------------------------------- | ------------------------ | ------------------------------------ |
| 用途     | 按需加载的领域能力（渐进式披露） | 启动时加载的持久上下文   | Agent 可调用的编程操作               |
| 加载时机 | Agent 判断相关时才读取           | Agent 启动时加载         | 每轮都可用                           |
| 格式     | 命名目录中的 `SKILL.md`          | `AGENTS.md` 文件         | 绑定到 Agent 的函数                  |
| 优先级   | 后来者覆盖（last wins）          | 用户级 + 项目级合并      | 创建时定义                           |
| 适用场景 | 任务专属、可能很大的指令集       | 始终相关的全局规范和偏好 | Agent 需要执行操作，或没有文件系统时 |

#### Skills 的最佳实践

- `description` 保持精简，`当{具体使用场景}的时候使用。{一句话功能简介}`
- `SKILL.md` 正文控制在 5000 tokens / 500 行以内，需要详细写的放到 `references/` 必要时加载
- 面向 Agent 而非人类写结构
  - 步骤化流程：明确的 1-2-3 步骤，而非段落式描述
  - 决策标准：遇到分支时如何选择（if X then A, else B）
  - 输入/输出示例（我觉得应该尽量用一般化示例）
  - 边界情况处理：常见异常如何应对
- 管控 Skill 数量

#### 感想

第一次有为 skill 增加访问权限的概念，确实在工程中，让 skill 包之间分离会比较方便后续维护以及影响最小化。

## 实践：AI 新闻助理的查重和旧闻比对改用 Skills

### `SKILL.md`

`news-dedup`：

```markdown
---
name: news-dedup
description: 当检查当前新闻文章列表中是否有重复新闻时使用。把重复新闻从当前新闻文章列表中剔除。
---

# news-dedup

## 步骤

1. 将当前新闻文章列表进行比较，检查是否存在重复或相似的新闻内容。
2. 如果当前新闻文章列表中有重复的新闻内容，则从新闻文章列表中删掉质量比较低的重复新闻。
3. 返回没有重复新闻的结构化的新闻文章列表。

## 示例
新闻1：公司A发布了新产品X，预计将于下个月上市。
新闻2：公司A的X，计划在下个月上市。其特性和功能也被介绍。
这两条新闻内容都属于同一条新闻，应该被视为重复新闻。根据质量比较低的原则，新闻2的内容更丰富，因此保留新闻2，删除新闻1。

新闻3：公司A的X。其市场定位和销售策略也进行了详细介绍。
这条新闻与新闻1和新闻2内容相似，但侧重点不同，因此不被视为重复新闻。

新闻4：公司A的新产品X的特性和功能。
这条新闻需要与新闻1和新闻2进行比较，如果内容相似度较高，侧重点一样，也应该被视为重复新闻。质量差不多的情况下，随机保留其中一条新闻即可。

## 边界情况

- 如果当前新闻文章列表为空，则返回空列表。
- 如果当前新闻文章列表中所有新闻都与其他新闻重复，则返回单一新闻文章。
- 如果当前新闻文章列表中只有一条新闻，则直接返回该新闻。
```

`history-check`：

```markdown
---
name: history-check
description: 当检查当前新闻文章列表中是否有/history/news_history.txt中的过往新闻时使用。把过往新闻从当前新闻文章列表中剔除。
---

# history-check

## 步骤

1. 读取/history/news_history.txt文件中的过往新闻列表。
2. 将当前新闻文章列表中的文章与过往新闻列表进行比较，检查是否存在重复或相似的新闻内容。
3. 如果当前新闻文章列表中有新闻文章与过往新闻列表中的任何一条新闻内容重复，则从新闻文章列表中删掉该新闻。
4. 全部检查结束之后，将当前新闻文章列表中没有重复的新闻文章追加到/history/news_history.txt文件中，确保过往新闻列表的完整性。
5. 返回没有过往新闻的结构化的新闻文章列表。

## news_history.txt写入格式
一行一条新闻，格式为：
日期 | 标题 | 摘要

## 示例
过往新闻：公司A发布了新产品X，预计将于下个月上市。
新闻1：公司A的X，计划在下个月上市。
新闻2：公司A的X。
这三种新闻内容都属于同一条新闻，应该被视为重复新闻。

新闻4：公司A的新产品X的特性和功能。
这个新闻需要与过往新闻进行比较，如果内容相似度较高，侧重点一样，也应该被视为重复新闻。

## 边界情况

- 如果当前新闻文章列表为空，则返回空列表。
- 如果/history/news_history.txt文件不存在或为空，则新建该文件并将当前新闻文章列表追加到该文件中，然后返回当前新闻文章列表。
- 如果当前新闻文章列表中所有新闻都与过往新闻列表中的新闻重复，则返回空列表。
```
